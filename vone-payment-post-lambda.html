Postman setup

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

These endpoints have no authentication requirement (see Common rules), so Interceptor/cookies aren't actually needed to call them — step 2–3 are only relevant if you also use this same Postman workspace against authenticated vOne endpoints.

Common rules

Headers

HeaderRequirementRule
Content-Typeoptionalapplication/json expected. If API Gateway delivers the body base64-encoded, it's decoded automatically before parsing.
OriginoptionalOnly affects CORS response headers (echoed back when it's https://vidyaone.com or a subdomain, https only). Not a request gate — a non-browser client with no Origin is still processed.
AuthorizationoptionalAccepted but not verified — these endpoints have no authentication requirement.

No authentication is required to call these endpoints.

Request body

The body is not field-validated — it must be a JSON object (otherwise 400), and that object is forwarded to the downstream queue consumer exactly as sent. There is no required/optional field list; any JSON object is accepted.

Repeating the same request does not deduplicate — each successful call queues a new message, even if the body is identical to a previous call.

Response envelope

Success: { "message": string, "requestId": string } (200). Error: { "error": string, "requestId": string }.

// success (200)
{ "message": "Payment event received", "requestId": "c4d1e2..." }

// error (400/404/405/500)
{ "error": "Request body is required", "requestId": "c4d1e2..." }

Payment

POST /

Accepts a payment event and queues it (mandatory) for downstream processing. The body is not field-validated — see Common rules.

Request

URL (Testing): https://api.vidyaone.com/payment

Headers: see Common rules.

Sample request

Body shape is not fixed — any JSON object is accepted and forwarded as-is. The following is illustrative only:

{
  "transactionId": "pay_9F3kL2Q",
  "amount": 4999.00,
  "currency": "INR",
  "status": "success",
  "userId": 10234
}

Response

200 — after the event is written to the queue.

{ "message": "Payment event received", "requestId": "c4d1e2..." }

400 — one of:

  • "Request body is required" — body missing.
  • "Request body is not valid base64: ..." — body marked base64-encoded but isn't valid base64/UTF-8.
  • "Request body exceeds 900000 bytes" — body larger than the configured cap.
  • "Request body must be valid JSON: ..." — body isn't valid JSON.
  • "Request body must be a JSON object" — body parsed but isn't a JSON object (e.g. an array or a bare string/number).

500 — "Internal server error". The event failed to queue, or an unexpected error occurred.

Events

Queues the event (mandatory) before the response is returned.

POST /payasguest

Accepts a guest payment event and queues it (mandatory) for downstream processing, to a separate queue from POST /. The body is not field-validated — see Common rules.

Request

URL (Testing): https://api.vidyaone.com/payment/payasguest

Headers: see Common rules.

Sample request

Body shape is not fixed — any JSON object is accepted and forwarded as-is. The following is illustrative only:

{
  "transactionId": "pay_9F3kL2Q",
  "amount": 4999.00,
  "currency": "INR",
  "status": "success",
  "userId": 10234
}

Response

200 — after the event is written to the queue.

{ "message": "Payment event received", "requestId": "c4d1e2..." }

400 — same messages as POST /.

500 — "Internal server error". The event failed to queue, or an unexpected error occurred.
