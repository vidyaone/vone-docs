vWebsite-plg-EnquiryAPI — Developer Guide

Postman setup guide

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — you don't need to set any auth header or cookie by hand.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

Common request & response rules

Authentication

Authentication required on every route documented in this guide.

Headers required on every request

HeaderRequiredNotes
Content-Type: application/jsonwrites onlyRequired on any request that carries a body.
Idempotency-Keymutating requestsA UUID the caller generates per request. Required on every POST / PUT / DELETE below. See the Idempotency line under each endpoint for what happens if you resend the same key/body.

Common query parameter

NameTypeRequiredNotes
productstringyesCalling client-app identifier, e.g. scl-website. Required on every route below.

Response envelope

Every response — success or failure — uses the same JSON shape:

{
  "success": true | false,
  "message": "human-readable string" | null,
  "errors":  [ { "code": "...", "message": "...", "field": "..." } ] | null,
  "data":    { ... } | [ ... ] | null
}

Success example:

{ "success": true, "message": "Success.", "errors": null, "data": { "enqId": 101 } }

Error example:

{
  "success": false,
  "message": "Validation failed.",
  "errors": [ { "code": "VALIDATION_FAILED", "message": "Either mobile or email is required.", "field": "PostDTO.mobile" } ],
  "data": null
}

Write routes return a short confirmation in message on success; read routes return null. Don't switch on it.

Each entry in errors[] has a machine-readable code — switch on code, not on message text.

JSON bodies accept numeric ids and numbers sent either as numbers or as quoted strings ("enqId": 101 and "enqId": "101" are equivalent).

All date-times are ISO-8601 and UTC. Request date-times must carry a UTC offset (Z or +00:00); any other offset fails with 400.

Status & error codes used in this guide

Enquiry

All routes below act only on enquiries belonging to the caller's own institution.

GET /enquiry

Returns a page of active, non-deleted enquiries for the calling institution, newest first (by creation date-time).

Request

ProductionGET https://api-vweb.vidyaone.com/plugin/enquiry?product={product}&pageNumber={pageNumber}&pageSize={pageSize}&statusId={statusId}&typeId={typeId}&sourceId={sourceId}&categoryId={categoryId}&createdDateFrom={createdDateFrom}&createdDateTo={createdDateTo}&mobile={mobile}&email={email}
Query paramTypeRequiredConstraints
pageNumberintegernoDefault 1. Must be > 0. A value past the last page is clamped back onto the last page.
pageSizeintegernoDefault 50. Must be > 0 and ≤ 200.
statusIdintegerno> 0. Exact match. Ids from GET /enquiry/options/status.
typeIdintegerno> 0. Exact match. Ids from GET /enquiry/options/type.

    &createdDateTo=2026-11-30T00:00:00Z    // optional, string, ISO-8601 date-time, UTC only — whole day, inclusive; >= createdDateFrom

POST /enquiry

Creates an enquiry for the calling institution. typeId decides which detail object is required and saved: 1 Student → student, 2 Parent → parent, 3 Teacher → job, 4 Other → other. Any other detail object sent is ignored.

Request

EnvironmentURL
TestingPOST https://api-vweb.vidyaone.com/test/plugin/enquiry?product={product}
ProductionPOST https://api-vweb.vidyaone.com/plugin/enquiry?product={product}
HeaderRequiredNotes
Content-Type: application/jsonyes
Idempotency-KeyyesCaller-generated UUID.

Idempotency: resending the same body creates another enquiry (200, new enqId) — duplicates are not detected.

Sample request body

{
  "postDTO": {                                 // required object
    "typeId": 1,                               // required, integer, one of 1 (Student), 2 (Parent), 3 (Teacher), 4 (Other)
    "categoryId": 1,                           // required, integer, > 0 — an active id from GET /enquiry/options/category
    "statusId": 1,                             // required, integer, > 0 — an active id from GET /enquiry/options/status
    "sourceId": 1,                             // required, integer, > 0 — an active id from GET /enquiry/options/source
    "mobile": "9876543210",                    // conditional, string, exactly 10 digits — mobile or email required; required when whatsApp=true
    "email": "meera.sharma@example.com",       // conditional, string, valid email, max 100 chars — mobile or email required
    "message": "Looking for admission in Class 2 for the coming session.", // optional, string
    "whatsApp": true,                          // optional, boolean, default false — true requires mobile
    "student": {                              // conditional object — required when the enquiry type is 1 (Student); ignored otherwise
      "studentName": "Aarav Sharma",            // required, string, max 150 chars
      "dob": "2018-04-12T00:00:00Z",            // optional, string, ISO-8601 date-time, UTC only
      "classAppliedFor": "Class 2"              // optional, string, max 20 chars
    },
    "parent": {                               // conditional object — required when the enquiry type is 2 (Parent); ignored otherwise
      "guardianName": "Meera Sharma",           // conditional, string, max 150 chars — guardianName or fatherName required
      "fatherName": "Rohit Sharma"              // conditional, string, max 150 chars — guardianName or fatherName required
    },
    "job": {                                  // conditional object — required when the enquiry type is 3 (Teacher); ignored otherwise
      "applicantName": "Priya Verma",           // required, string, max 150 chars
      "positionAppliedFor": "Maths Teacher",    // optional, string, max 100 chars
      "qualification": "M.Sc, B.Ed",            // optional, string, max 150 chars
      "yearOfExperience": 4.5                   // optional, number, 0–999.9, one decimal place
    },
    "other": {                                // conditional object — required when the enquiry type is 4 (Other); ignored otherwise
      "contactPersonName": "Neha Gupta"         // required, string, max 150 chars
    }
  }
}

Contact rules (both create and update): at least one of mobile / email must be non-blank; mobile must be exactly 10 digits; mobile is required when whatsApp is true; email must be a valid address, max 100 chars. Text values are stored trimmed; blank optional text is stored as null.

POST /enquiry/followup

Adds a follow-up to an enquiry of the calling institution. When statusId is sent (and > 0), the enquiry's status is set to it in the same call — if either part fails, neither is saved. statusId 0 or omitted leaves the status unchanged.

Request

EnvironmentURL
TestingPOST https://api-vweb.vidyaone.com/test/plugin/enquiry/followup?product={product}
ProductionPOST https://api-vweb.vidyaone.com/plugin/enquiry/followup?product={product}
HeaderRequiredNotes
Content-Type: application/jsonyes
Idempotency-KeyyesCaller-generated UUID.

Idempotency: resending the same body adds another follow-up (200, new followupId) — duplicates are not detected.

Sample request body

{
  "enqId": 101,                                                     // required, integer, > 0
  "followUp": {                                                     // required object
    "comment": "Called the parent; campus visit planned for next week.", // required, string, stored trimmed
    "date": "2026-11-14T10:00:00Z"                                  // required, string, ISO-8601 date-time, UTC only
  },
  "statusId": 2                                                     // optional, integer, >= 0 — an active id from GET /enquiry/options/status; 0 or omitted = keep the current status
}

Response

200 OK

{
  "success": true,
  "message": "Success.",
  "errors": null,
  "data": { "followupId": 201 }
}
StatuscodeFires when
400VALIDATION_FAILEDenqId not > 0; followUp missing; followUp.comment empty; followUp.date missing or not UTC; statusId negative; or the body is missing / not valid JSON.
400INVALID_INPUTstatusId (> 0) isn't an active status option, or a submitted value is not allowed.
400REQUIRED_FIELDproduct missing, or a required value is missing.
401UNAUTHORIZEDAuthentication required.
404RECORD_NOT_FOUNDNo active enquiry with this enqId for the calling institution (missing or deleted).
409FOREIGN_KEY_VIOLATIONA referenced record was removed while the request was being processed.
DELETE /enquiry/followup

Deletes up to 200 follow-ups of the calling institution's enquiries. Each id succeeds or fails on its own: an id that doesn't exist, is already deleted, or belongs to another institution's (or a deleted) enquiry is reported with success: false and doesn't fail the request. Deleted follow-ups no longer appear in any route.

Request

EnvironmentURL
TestingDELETE https://api-vweb.vidyaone.com/test/plugin/enquiry/followup?product={product}
ProductionDELETE https://api-vweb.vidyaone.com/plugin/enquiry/followup?product={product}
HeaderRequiredNotes
Content-Type: application/jsonyes
Idempotency-KeyyesCaller-generated UUID.

Idempotency: resending the same body returns 200; ids deleted by the first call are reported with success: false.

Sample request body

{
  "followupIds": [201, 202]   // required, array of integers, 1–200 items, each > 0, no duplicates
}

Response

200 OK

{
  "success": true,
  "message": "Enquiry follow-up deleted successfully.",
  "errors": null,
  "data": {
    "totalCount": 2,
    "successCount": 1,
    "failureCount": 1,
    "results": [
      { "followupId": 201, "success": true },
      { "followupId": 202, "success": false }
    ]
  }
}

results has one entry per requested id, in request order.

StatuscodeFires when
400VALIDATION_FAILEDfollowupIds empty, more than 200 ids, contains duplicates, or any id not > 0; or the body is missing / not valid JSON.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.
