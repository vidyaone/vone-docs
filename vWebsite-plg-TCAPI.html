vWebsite-plg-TCAPI — Developer Guide

Documents the TC (Transfer Certificate) resource.

Postman setup guide

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — you don't need to set any auth header or cookie by hand.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

Common request & response rules

Authentication

Authentication required on every route documented in this guide.

Headers required on every request

HeaderRequiredNotes
Content-Type: application/jsonwrites onlyRequired on any request that carries a body.
Idempotency-Keymutating requestsA UUID the caller generates per request. Required on every POST / PUT / DELETE below. See the Idempotency line under each endpoint for what happens if you resend the same key/body.

Common query parameter

NameTypeRequiredNotes
productstringyesCalling client-app identifier, e.g. scl-website. Required on every route below.

Response envelope

Every response — success or failure — uses the same JSON shape:

{
  "success": true | false,
  "message": "human-readable string" | null,
  "errors":  [ { "code": "...", "message": "...", "field": "..." } ] | null,
  "data":    { ... } | [ ... ] | true | false | null
}

Success example:

{ "success": true, "message": null, "errors": null, "data": { "tcId": 301, "wasUpdated": false, "filePresign": null, "imagePresign": null } }

Error example:

{
  "success": false,
  "message": "Validation failed.",
  "errors": [ { "code": "VALIDATION_FAILED", "message": "studentName is required.", "field": "Tc.StudentName" } ],
  "data": null
}

Each entry in errors[] has a machine-readable code — switch on code, not on message text.

JSON bodies accept numeric ids and numbers sent either as numbers or as quoted strings ("tcId": 301 and "tcId": "301" are equivalent).

TC

All routes below act only on TC records belonging to the caller's own institution.

POST /tc

Creates a TC for the calling institution — or, if regNo or srNo matches a record that already exists for this institution, updates that record in place instead of creating a duplicate (an upsert).

Request

EnvironmentURL
TestingPOST https://api-vweb.vidyaone.com/test/plugin/tc?product={product}
ProductionPOST https://api-vweb.vidyaone.com/plugin/tc?product={product}

Sample request body

{
  "tc": {
    "studentName": "Asha Mehta",         // required, string, max 150 chars
    "regNo": "REG-2026-0042",            // conditional, string, max 50 chars — at least one of regNo/srNo is required
    "srNo": "SR-1123",                   // conditional, string, max 50 chars — at least one of regNo/srNo is required
    "dob": "2015-04-12T00:00:00Z",       // required, string, ISO-8601 date-time, UTC only (offset +00:00 or Z) — any other offset fails validation
    "fatherName": "Raj Mehta",           // required, string, max 150 chars
    "className": "8",                    // required, string, max 20 chars
    "sectionName": "B",                  // optional, string, max 10 chars
    "fileSrc": "tc-asha-mehta.pdf",       // optional, string, max 500 chars — a plain file name only, never a URL or a path; see "Uploading a document or image" below — independent of uploadFileFileName/uploadImageFileName, never required to match either
    "imageSrc": "asha-mehta.jpg"          // optional, string, max 500 chars — a plain file name only, never a URL or a path; see "Uploading a document or image" below
  },
  "uploadFileFileName": "asha-mehta-tc-raw.pdf",  // optional, string, max 200 chars — requests a document upload slot; see "Uploading a document or image" below
  "uploadImageFileName": "asha-mehta-raw.jpg"     // optional, string, max 200 chars — requests an image upload slot; see "Uploading a document or image" below
}

regNo/srNo is a single either/or requirement — sending one without the other is valid. fileSrc/imageSrc are each independently optional — either, both, or neither may be sent.

Uploading a document or image

fileSrc/imageSrc and uploadFileFileName/uploadImageFileName are unrelated fields — fileSrc/imageSrc are stored exactly as sent, and this API never requires either to match anything the upload flow produces.

Sending uploadFileFileName and/or uploadImageFileName returns a presigned S3 upload for each, resolved after the TC is already created/updated — an unsupported or unsafe file name fails the request with 400 INVALID_INPUT, but the TC has already been saved by that point (look it up via List TCs or Get TC (view) if this happens). On success, POST the raw file bytes plus every field in data.filePresign.post.fields / data.imagePresign.post.fields directly to the matching post.url (as multipart form fields, file field last) within expiresIn seconds. Re-uploading the same file name for the same institution overwrites the previous object at that key.

UploadAllowed extensions (case-insensitive)Max size
uploadFileFileNamepdf10 MB (10485760 bytes)
uploadImageFileNamejpg, jpeg, png, gif, webp, bmp10 MB (10485760 bytes)

Also rejected, after the 200-character check above (so still possible after the TC is already saved): a name containing a path separator (/ or \), .., a control character, a missing extension, or a second, disguised extension (e.g. invoice.php.jpg).

Response

200 OK

{
  "success": true,
  "message": null,
  "errors": null,
  "data": {
    "tcId": 301,
    "wasUpdated": false,
    "filePresign": {
      "key": "vWebsite/plugin_cdn/tc_files/SAASX7Y8Z9/asha-mehta-tc-raw.pdf",
      "post": {
        "url": "https://vidyaone-data-lake.s3.ap-south-1.amazonaws.com/",
        "fields": {
          "key": "vWebsite/plugin_cdn/tc_files/SAASX7Y8Z9/asha-mehta-tc-raw.pdf",
          "x-amz-server-side-encryption": "AES256",
          "x-amz-credential": "ASIAEXAMPLE/20261012/ap-south-1/s3/aws4_request",
          "x-amz-algorithm": "AWS4-HMAC-SHA256",
          "x-amz-date": "20261012T000000Z",
          "policy": "eyJleHBpcmF0aW9uIjoiMjAyNi0xMC0xMlQwMDowMjowMFoi...",
          "x-amz-signature": "a1b2c3d4e5f6..."
        }
      },
      "expiresIn": 120,
      "maxFileSize": 10485760,
      "contentTypePrefix": "application/"
    },
    "imagePresign": {
      "key": "vWebsite/plugin_cdn/tc_images/SAASX7Y8Z9/asha-mehta-raw.jpg",
      "post": { "url": "https://vidyaone-data-lake.s3.ap-south-1.amazonaws.com/", "fields": { "...": "..." } },
      "expiresIn": 120,
      "maxFileSize": 10485760,
      "contentTypePrefix": "image/"
    }
  }
}

filePresign/imagePresign are each null unless the matching uploadFileFileName/uploadImageFileName was sent. wasUpdated is true when regNo or srNo matched an existing record for this institution and that record was updated in place rather than a new one created — tcId is then the existing record's id.

StatuscodeFires when
400VALIDATION_FAILEDA field constraint above fails (including the either/or rule on regNo/srNo), or the body is missing / invalid.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.
409DUPLICATE_RECORDregNo matches one existing record for this institution and srNo matches a different existing record — ambiguous, so neither is updated.
400INVALID_INPUTuploadFileFileName/uploadImageFileName has an unsupported or unsafe value (see "Uploading a document or image" above) — the TC is still saved; only the affected upload slot fails.

Idempotency. Sending the same Idempotency-Key and body again: since at least one of regNo/srNo is always present and now matches the record just created, the second call updates that same record in place (data.wasUpdated: true) rather than creating a duplicate — tcId is unchanged.

POST /tc/bulk

Creates or updates up to 200 TCs for the calling institution in one call. Partial success — each row is validated and upserted independently (same matching rule as Create TC), and the response reports a per-row outcome instead of rejecting the whole batch for one bad row. This route accepts no upload-related fields — it never returns a presign.

Request

EnvironmentURL
TestingPOST https://api-vweb.vidyaone.com/test/plugin/tc/bulk?product={product}
ProductionPOST https://api-vweb.vidyaone.com/plugin/tc/bulk?product={product}

Sample request body

{
  "items": [                              // required, array, 1–200 items
    {
      "studentName": "Asha Mehta",         // required, string, max 150 chars
      "regNo": "REG-2026-0042",            // conditional, string, max 50 chars — at least one of regNo/srNo is required per item
      "srNo": "SR-1123",                   // conditional, string, max 50 chars
      "dob": "2015-04-12T00:00:00Z",       // required, string, ISO-8601 date-time, UTC only
      "fatherName": "Raj Mehta",           // required, string, max 150 chars
      "className": "8",                    // required, string, max 20 chars
      "sectionName": "B",                  // optional, string, max 10 chars
      "fileSrc": "tc-asha-mehta.pdf",       // optional, string, max 500 chars
      "imageSrc": "asha-mehta.jpg"          // optional, string, max 500 chars
    },
    {
      "studentName": "Rohan Iyer",
      "regNo": "REG-2026-0043",
      "srNo": "SR-1124",
      "dob": "2014-08-30T00:00:00Z",
      "fatherName": "Suresh Iyer",
      "className": "8",
      "sectionName": "B",
      "fileSrc": "tc-rohan-iyer.pdf",
      "imageSrc": null
    }
  ]
}

Each item follows the same field rules as Create TC's tc object — including the either/or requirement on regNo/srNo — applied per item, not to the batch as a whole.

Response

200 OK

{
  "success": true,
  "message": null,
  "errors": null,
  "data": {
    "totalCount": 2,
    "successCount": 1,
    "failureCount": 1,
    "results": [
      { "index": 0, "success": true, "tcId": 301, "wasUpdated": false, "error": null },
      { "index": 1, "success": false, "tcId": null, "wasUpdated": false, "error": "regNo matches one existing record for this institution and srNo matches a different existing record; cannot determine which to update." }
    ]
  }
}

index matches the item's position in the request's items array. error is a human-readable message, not a machine-readable code — it carries either a field-validation message or a match-conflict message for that row only; it never aborts the rest of the batch. wasUpdated has the same meaning per row as on Create TC.

If two items in the same request share the same regNo or srNo and neither matches a record that already existed before this request, only the first succeeds — the second fails (success: false) with a duplicate error for that field, rather than updating the first item's row.

StatuscodeFires when
400VALIDATION_FAILEDitems is empty or missing, contains more than 200 records, or the body is missing / invalid. (Per-item field errors never produce this status — they appear in data.results[] instead.)
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.

Idempotency. Sending the same Idempotency-Key and body again: every item whose regNo/srNo matches a row created by the first call now updates that row in place (wasUpdated: true) instead of creating a duplicate.

Updates a TC belonging to the calling institution. Every writable field is overwritten with the value sent — there is no partial update. Unlike Create TC, this is a plain update by tcId, not an upsert — it never creates a new record.

EnvironmentURL

Request

EnvironmentURL
TestingDELETE https://api-vweb.vidyaone.com/test/plugin/tc?product={product}&tcIds={tcIds}
ProductionDELETE https://api-vweb.vidyaone.com/plugin/tc?product={product}&tcIds={tcIds}
Query paramTypeRequiredConstraints
tcIdsinteger, repeatedyes1–200 values, each > 0. Repeat the key for each id (tcIds=301&tcIds=302). A value outside these constraints fails the whole request — it is not reported per-id.

Sample request

DELETE /tc?product=scl-website

Response

200 OK

{
  "success": true,

  "errors": null,

    "totalCount": 2,
    "successCount": 1,
    "failureCount": 1,

success: false on an item means no matching active TC existed for this institution at that tcId (already deleted, or never existed) — it carries no separate error message or code.
