vSoftware-EnquiryAPI — Developer Guide

Postman setup

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — you don't need to set any auth header or cookie by hand.
  4. Download the collection from the navbar link above and import it into Postman, then send requests — it's pre-configured for Testing.

Common rules

Headers

  • Content-Type: application/json on every request that sends a body (POST/PUT).
  • Idempotency-Key: caller-generated UUID, required on every POST/PUT/DELETE. See each route below for what repeating the same request actually does.
  • Authentication required on every route below.

Shared query parameter

Every single route also requires:

ParamTypeRequiredNotes
productstringrequiredProduct/subdomain identifier.

Response envelope

Every response — success or failure — has this shape:

{
  "success": boolean,
  "message": string | null,
  "data": object | null,
  "errors": [ { "code": string, "message": string, "field": string | null } ] | null
}

Success example:

{
  "success": true,
  "message": "Success.",
  "data": 101,
  "errors": null
}

Error example:

{
  "success": false,
  "message": "Validation failed.",
  "data": null,
  "errors": [
    { "code": "VALIDATION_FAILED", "message": "StatusName is required.", "field": "postDTO.statusName" }
  ]
}

Switch on errors[].code — never on the message text.

Status codes and error codes

StatusCodeWhen
200—Request succeeded.
400VALIDATION_FAILEDA request field failed validation (missing, too long, out of range).
400REQUIRED_FIELDproduct query parameter is missing.
401UNAUTHORIZEDAuthentication cookie missing or invalid.
404RECORD_NOT_FOUNDThe record doesn't exist, doesn't belong to your institute, is already in that state, or was changed by another request first.
409DUPLICATE_RECORDA record with that name already exists for your institute.
409INVALID_STATEThe request conflicts with the record's current state (e.g. trying to change an enquiry's subtype).
409DEPENDENT_RECORDS_EXISTBlocked because a dependent record still exists (e.g. a status/source still used by a non-deleted enquiry).
500INTERNAL_ERRORUnexpected server error.

Status

POST /enquiry/setting/status

Creates an enquiry status for your institute.

Request

EnvironmentURL
Testinghttps://api-vsof.vidyaone.com/test/enquiry/setting/status?product=scl-software

Headers: Content-Type: application/json, Idempotency-Key: <uuid>

Sample request

POST /enquiry/setting/status?product=scl-software
{
  "postDTO": {                   // required object
    "statusName": "Open"         // required, string, max 100 chars
  }
}

Response

200

{ "success": true, "message": "Success.", "data": 101, "errors": null }

data is the new status's id.

StatusCodeCondition
400VALIDATION_FAILEDstatusName missing or over 100 characters.
409DUPLICATE_RECORDA status with this name (case-insensitive) already exists for your institute.

Repeating the same request body returns 409 DUPLICATE_RECORD once the first call has created the status — the name now already exists.

Enquiry

POST /enquiry/setting/enquiry

Creates an enquiry for your institute. Exactly one of parentDetail, studentDetail, applicantDetail, supplierDetail or otherDetail must be provided — whichever one you send fixes the enquiry's subtype, which cannot be changed afterwards.

Request

EnvironmentURL
Testinghttps://api-vsof.vidyaone.com/test/enquiry/setting/enquiry?product=scl-software

Headers: Content-Type: application/json, Idempotency-Key: <uuid>

Sample request

POST /enquiry/setting/enquiry?product=scl-software
{
  "postDTO": {                             // required object
    "typeId": 1,                             // required, integer, > 0
    "categoryId": 2,                         // required, integer, > 0
    "statusId": 101,                         // required, integer, > 0
    "sourceId": 201,                         // required, integer, > 0
    "emailAddress": "parent@example.com",    // optional, string, max 150 chars, valid email
    "details": "Interested in Grade 3 admission for next year.",  // optional, string
    "phoneCode": "+91",                      // required, string, max 5 chars, pattern +<country code>
    "phone": "9876543210",                   // required, string, 6 to 15 digits
    "isWhatsappNumber": true,                // optional, boolean, default false
    "address": "12 MG Road, Bengaluru",      // optional, string, max 500 chars
    "countryId": 1,                          // optional, integer
    "stateId": 26,                           // optional, integer
    "districtId": 49,                        // optional, integer
    "pincode": "560001",                     // optional, string, max 10 chars
    "parentDetail": {                        // exactly one of the 5 detail objects below is required — the rest must be omitted or null
      "studentName": "Aarav Shah",             // required, string, max 150 chars
      "studentDob": "2015-06-12",              // optional, string, ISO-8601 date
      "classId": 3,                            // optional, integer
      "guardianName": "Raj Shah",              // required, string, max 150 chars
      "relationId": 1                          // optional, integer
    },
    "studentDetail": null,                   // conditional, object — see studentDetail shape below; omit/null unless this is the chosen subtype
    "applicantDetail": null,                 // conditional, object — see applicantDetail shape below
    "supplierDetail": null,                  // conditional, object — see supplierDetail shape below
    "otherDetail": null                      // conditional, object — see otherDetail shape below
  }
}

The other 4 detail shapes, each used the same way (exactly one of the 5 populated):

// studentDetail
{
  "studentName": "Priya Nair",   // required, string, max 150 chars
  "fatherName": "Suresh Nair",   // optional, string, max 150 chars
  "classId": 5                   // optional, integer
}
// applicantDetail
{
  "applicantName": "Vikram Rao",  // required, string, max 150 chars
  "positionId": 2,                // optional, integer
  "qualification": "B.Ed",        // optional, string, max 200 chars
  "yearsOfExperience": 3.5        // optional, decimal, >= 0
}
// supplierDetail
{
  "companyName": "ABC Stationers",   // required, string, max 200 chars
  "serviceOrProductType": "Books",   // optional, string, max 200 chars
  "gstNumber": "29ABCDE1234F1Z5",    // optional, string, max 25 chars, valid GSTIN
  "personName": "Mohan Das"          // optional, string, max 150 chars
}
// otherDetail
{
  "contactPerson": "Unknown Caller"  // required, string, max 150 chars
}

Response

200

{ "success": true, "message": "Success.", "data": 301, "errors": null }

data is the new enquiry's id.

StatusCodeCondition
400VALIDATION_FAILEDA required field is missing/invalid, or zero or more than one detail object was provided.
404RECORD_NOT_FOUNDtypeId/categoryId not found, or statusId/sourceId not found for your institute.

There is no uniqueness constraint on enquiries — repeating the same request body creates a separate new enquiry each time.
