vone-cart-get-lambda

Reads and deletes cart items saved for a guest/user session.

Postman setup

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — no auth header or cookie to set by hand.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

Common rules

Headers

No request headers are required on either route. Neither GET /website/cart nor DELETE /website/cart takes a request body, so no Content-Type is needed. Neither route reads an Idempotency-Key header — DELETE is naturally idempotent instead: repeating the same delete after it already succeeded returns 404 Item not found, not an error or a second effect.

No authentication is required on either route — both are reachable by anyone who supplies a valid guest_id/user_id (and, for delete, item_id).

Shared query parameters

ParameterTypeRequirementRule
guest_idstringconditionalNon-blank after trim, 1–100 chars, ^[A-Za-z0-9_-]+$ only. Required unless user_id is supplied.
user_idinteger (as string)conditionalDigits only, ^[0-9]{1,20}$, value > 0. Required unless guest_id is supplied.

Read from the query string only — no path-parameter or body fallback. Supplying neither guest_id nor user_id is a 400. Each parameter is validated independently: a present-but-malformed value is a 400 even if the other parameter is valid or absent.

Response envelope

Every response (except the 204 OPTIONS preflight) is shaped:

{ "success": bool, "message": string, "errors": null, "data": ... }

Success example:

{ "success": true, "message": "", "errors": null, "data": [] }

Error example:

{ "success": false, "message": "Query parameter 'guest_id' must not be blank", "errors": null, "data": [] }

There is no code field in this project — only HTTP status and a human-readable message. errors is always null. data is a list on GET success, an object on DELETE success, and always [] on any error from either route.

Status summary

StatusRoute(s)Condition
204anyOPTIONS preflight — returned immediately, no processing, no body.
200GETQuery succeeded (possibly with an empty list).
200DELETEItem found and deleted.
400anyA query parameter is missing/malformed — see each route's Request section.
404DELETENo item matched item_id for the given guest_id/user_id (never existed, already deleted, or belongs to a different guest/user).
405anyMethod other than GET, DELETE, or OPTIONS.
500anyUnexpected error (DynamoDB outage, missing IAM permission, bad table config, etc.). The real cause is logged server-side only — the response never leaks it.

CORS

Applied only when the request's Origin header is https://vidyaone.com or any https://*.vidyaone.com subdomain — plain http and unrecognized origins get no CORS headers, so a browser blocks the page from reading the response (non-browser callers are unaffected; the body is still returned). Access-Control-Allow-Methods: GET,DELETE,OPTIONS. An OPTIONS request always gets an immediate 204 with no body, before any parameter validation runs.

Cart

GET /website/cart

Returns every cart item saved for a guest_id and/or user_id.

Request

Testing URL: https://api.vidyaone.com/website/cart

No headers required. Query parameters: see Common rules above (guest_id, user_id).

Sample request

GET /website/cart?guest_id=guest_a1b2c3d4   // conditional, string, 1-100 chars, ^[A-Za-z0-9_-]+$ — required unless user_id is given
    &user_id=4071                            // conditional, integer as string, 1-20 digits, > 0 — required unless guest_id is given

Supplying both merges the two lookups and de-duplicates the result (the guest_id copy of a match wins). Supplying either alone is equally valid.

200 — empty cart (no error; a never-used or fully-emptied guest_id/user_id is not distinguishable, and isn't treated as one):

{ "success": true, "message": "", "errors": null, "data": [] }

400 — one of:

  • Provide at least one of query parameters 'guest_id' or 'user_id'
  • Query parameter 'guest_id' must not be blank
  • Query parameter 'guest_id' contains invalid characters
  • Query parameter 'user_id' must not be blank
  • Query parameter 'user_id' must be a positive integer

500 — Internal server error (see Status summary above).

DELETE /website/cart

Deletes a single cart item by item_id, scoped to guest_id and/or user_id.

Request

Testing URL: https://api.vidyaone.com/website/cart

No headers required. Query parameters: item_id (below) plus guest_id/user_id from Common rules above.

ParameterTypeRequirementRule
item_idstringrequiredNon-blank after trim, 1–100 chars, ^[A-Za-z0-9_-]+$ only.

Sample request

DELETE /website/cart?item_id=a1b2c3d4-5e6f-4a1b-9c3d-7f8e9a0b1c2d   // required, string, 1-100 chars, ^[A-Za-z0-9_-]+$
    &guest_id=guest_a1b2c3d4                                        // conditional, string, 1-100 chars, ^[A-Za-z0-9_-]+$ — required unless user_id is given
    &user_id=4071                                                   // conditional, integer as string, 1-20 digits, > 0 — required unless guest_id is given

Response

200 — item found and deleted:

{
  "success": true,
  "message": "Item deleted",
  "errors": null,
  "data": { "itemId": "a1b2c3d4-5e6f-4a1b-9c3d-7f8e9a0b1c2d" }
}

404 — no item matched item_id for the given guest_id/user_id (never existed, already deleted, or belongs to a different guest/user):

{ "success": false, "message": "Item not found", "errors": null, "data": [] }

400 — one of:

  • Query parameter 'item_id' is required
  • Query parameter 'item_id' must not be blank
  • Query parameter 'item_id' contains invalid characters
  • Provide at least one of query parameters 'guest_id' or 'user_id'
  • Query parameter 'guest_id' must not be blank
  • Query parameter 'guest_id' contains invalid characters
  • Query parameter 'user_id' must not be blank
  • Query parameter 'user_id' must be a positive integer

500 — Internal server error (see Status summary above).
