vone-cart-payasguest-lambda

Returns a guest's pay-as-guest cart summary and totals, and records a Razorpay payment for that guest.

Postman setup

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — no auth header or cookie to set by hand.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

Common rules

Headers

GET /website/cart/payasguest takes no request body, so no Content-Type is needed. POST /website/cart/payasguest requires Content-Type: application/json.

No Idempotency-Key header is read on either route. Repeating the same POST body (same payment_transaction_id) does not return a conflict — it silently overwrites the previously saved record for that guest_id/payment_transaction_id pair with the new body.

No authentication is required on either route — both are reachable by anyone who supplies a valid guest_id.

Response envelope

Every response (except the 204 OPTIONS preflight) is shaped:

{ "success": bool, "message": string, "errors": null, "data": {} }

Success example:

{ "success": true, "message": "", "errors": null, "data": { } }

Error example:

{ "success": false, "message": "Query parameter 'guest_id' is required", "errors": null, "data": {} }

There is no code field in this project — only HTTP status and a human-readable message. errors is always null. data is always an object: on GET success it's the summary/totals object; on POST success it's the exact body that was sent, echoed back unchanged; on any error from either route it's {}.

Status summary

StatusRoute(s)Condition
204anyOPTIONS preflight — returned immediately, no processing, no body.
200GETAt least one pay-as-guest item is awaiting payment for the given guest_id.
200POSTThe payment record was saved.
400anyRequest input missing/malformed — see each route's Request section.
404GETNo pay-as-guest item is currently awaiting payment for the given guest_id.
405anyMethod other than GET, POST, or OPTIONS.
500anyUnexpected error (DynamoDB outage, missing IAM permission, bad table config, etc.). The real cause is logged server-side only — the response never leaks it.

CORS

Applied only when the request's Origin header is https://vidyaone.com or any https://*.vidyaone.com subdomain — plain http and unrecognized origins get no CORS headers, so a browser blocks the page from reading the response (non-browser callers are unaffected; the body is still returned). Access-Control-Allow-Methods: GET,POST,OPTIONS. An OPTIONS request always gets an immediate 204 with no body, before any input validation runs.

Cart

GET /website/cart/payasguest

Returns a summarized line list plus aggregated totals for every pay-as-guest cart item currently awaiting payment for guest_id.

Request

Testing URL: https://api.vidyaone.com/website/cart/payasguest

No headers required.

ParameterTypeRequirementRule
guest_idstringrequiredNon-blank after trim, 1–100 chars, ^[A-Za-z0-9_-]+$ only.

Sample request

GET /website/cart/payasguest?guest_id=guest_a1b2c3d4   // required, string, 1-100 chars, ^[A-Za-z0-9_-]+$

An item keeps appearing in this response on every call, including ones where it already appeared before, until a POST /website/cart/payasguest call records a payment that covers it — after that, it stops appearing here.

Response

200:

{
  "success": true,
  "message": "",
  "errors": null,
  "data": {
    "guestId": "guest_a1b2c3d4",
    "prodSummery": "1. Pro Plan-Pro - Monthly VidyaOne Pro Plan 999.00\n2. School Website-Premium Support Starter Pack 4999.00",
    "totalAmt": 5998.00,
    "totalDis": 600.00,
    "netPayable": 5398.00
  }
}
FieldTypeNotes
guestIdstringEchoes the guest_id query parameter.
prodSummerystringOne line per item, newline-separated, formatted <position>. <productName>-<planName> <itemName> <price> (price with 2 decimals).
totalAmtnumberSum of every item's price, rounded to 2 decimals.
totalDisnumberSum of every item's discount, rounded to 2 decimals.
netPayablenumbertotalAmt - totalDis, rounded to 2 decimals.

404 — no pay-as-guest item is currently awaiting payment for guest_id (never added one, already paid for all of them, or none are flagged pay-as-guest):

{ "success": false, "message": "No pay-as-guest cart items found for this guest", "errors": null, "data": {} }

400 — one of:

  • Query parameter 'guest_id' is required
  • Query parameter 'guest_id' must not be blank
  • Query parameter 'guest_id' contains invalid characters

500 — Internal server error (see Status summary above).

POST /website/cart/payasguest

Records a Razorpay payment for a guest. When the body includes both guest_id and payment_transaction_id, every pay-as-guest item this guest_id currently has awaiting payment (per GET /website/cart/payasguest above) is marked paid immediately after this call succeeds, stamped with payment_transaction_id — a subsequent GET no longer returns those items.

Request

Testing URL: https://api.vidyaone.com/website/cart/payasguest

Headers: Content-Type: application/json.

No field in the body is enforced by the server — any JSON object is accepted and saved as-is. guest_id and payment_transaction_id are the only two fields that have any effect beyond being stored: both must be present and non-blank for the paid-item update described above to run.

Sample request

{
  "school_name": "This is a test submission",       // optional, string — stored as-is
  "email_id": "richardjohnson@zylker.com",           // optional, string — stored as-is
  "mobile_no": "xxxxxxxxxx",                          // optional, string — stored as-is
  "payment_amount": "50.00",                          // optional, string — stored as-is, not verified against the cart total
  "payment_status": "Completed",                      // optional, string — stored as-is; its value has no effect on whether items are marked paid
  "payment_transaction_id": "xxxxxxxxxx",             // conditional, string — combined with guest_id, drives the paid-item update
  "time": "10.00 AM",                                 // optional, string — stored as-is
  "guest_id": "This is a test submission",            // conditional, string — combined with payment_transaction_id, drives the paid-item update
  "saas_code": "This is a test submission",           // optional, string — stored as-is
  "institute_address": "This is a test submission",  // optional, string — stored as-is
  "total_amount": "0.12",                              // optional, string — stored as-is
  "total_discount": "0.12",                            // optional, string — stored as-is
  "net_payable": "100",                                 // optional, string — stored as-is
  "payment_currency": "USD",                            // optional, string — stored as-is
  "ip_address": "xxx.xxx.xxx.xxx"                        // optional, string — stored as-is
}
