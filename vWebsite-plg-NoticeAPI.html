vWebsite-plg-NoticeAPI — Developer Guide

Documents the Notice resource.

Postman setup guide

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — you don't need to set any auth header or cookie by hand.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

Common request & response rules

Common query parameter

NameTypeRequiredNotes

Response envelope

Every response — success or failure — uses the same JSON shape:

{
  "success": true | false,
  "message": "human-readable string" | null,
  "errors":  [ { "code": "...", "message": "...", "field": "..." } ] | null,
  "data":    { ... } | [ ... ] | true | false | null
}

Success example:

{ "success": true, "message": null, "errors": null, "data": { "noticeId": 501, "imagePresign": null } }

Error example:

{
  "success": false,
  "message": "Validation failed.",
  "errors": [ { "code": "VALIDATION_FAILED", "message": "title is required and must be at most 200 characters.", "field": "Notice.Title" } ],
  "data": null
}

Each entry in errors[] has a machine-readable code — switch on code, not on message text.

JSON bodies accept numeric ids and numbers sent either as numbers or as quoted strings ("noticeId": 501 and "noticeId": "501" are equivalent).

Notice

All routes below act only on notices belonging to the caller's own institution.

GET /notice

Returns every active, non-deleted notice for the calling institution, most recently published first. Not paged. Reads from the vw_plg_notice_list read model.

Request

EnvironmentURL
TestingGET https://api-vweb.vidyaone.com/test/plugin/notice?product={product}
ProductionGET https://api-vweb.vidyaone.com/plugin/notice?product={product}

Sample request

GET /notice?product=scl-website

Response

200 OK

{
  "success": true,
  "message": null,
  "errors": null,
  "data": [
    {
      "noticeId": 501,
      "instSaaSId": 321,
      "title": "Annual Sports Day",
      "shortDescription": "Join us for the annual sports day on the school grounds.",
      "imageSrc": "sports-day.jpg",
      "publishDate": "2026-11-01",
      "expiryDate": "2026-11-15",
      "publishState": "Live",
      "isActive": true,
      "createdAt": "2026-10-10T08:00:00+00:00",
      "updatedAt": "2026-10-10T08:00:00+00:00"
    }
  ]
}

shortDescription is the first 150 characters of the notice's full description. publishState is computed from publishDate/expiryDate against the current UTC date — "Scheduled" (publish date is in the future), "Live", or "Expired" (expiry date has passed) — never stored. isActive is always true in current practice: no route in this API deactivates a notice.

StatuscodeFires when
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.

POST /notice

Creates a new notice for the calling institution.

Request

EnvironmentURL
TestingPOST https://api-vweb.vidyaone.com/test/plugin/notice?product={product}
ProductionPOST https://api-vweb.vidyaone.com/plugin/notice?product={product}

Sample request body

{
  "notice": {
    "title": "Annual Sports Day",                                             // required, string, max 200 chars
    "description": "Join us for the annual sports day on the school grounds.", // required, string
    "imageSrc": "sports-day.jpg",                                             // optional, string, max 500 chars — a plain file name only, never a URL or a path; see "Uploading an image" below — independent of uploadImageFileName, never required to match it
    "publishDate": "2026-11-01",                                              // required, string, date (yyyy-MM-dd)
    "expiryDate": "2026-11-15"                                                // optional, string, date (yyyy-MM-dd) — must be on or after publishDate
  },
  "uploadImageFileName": "sports-day-raw.jpg"                                 // optional, string, max 255 chars — requests an image upload slot; see "Uploading an image" below
}

Uploading an image

imageSrc and uploadImageFileName are unrelated fields — imageSrc is stored exactly as sent, and this API never requires it to match anything the upload flow produces.

Sending uploadImageFileName returns a presigned S3 upload in the response, resolved after the notice is already created — an unsupported or unsafe file name fails the request with 400 INVALID_INPUT, but the notice has already been created by that point (data.noticeId in the error is not returned, but the record exists — look it up via List notices or Get notice (view) if this happens). On success, POST the raw file bytes plus every field in data.imagePresign.post.fields directly to data.imagePresign.post.url (as multipart form fields, file field last) within expiresIn seconds. Re-uploading the same file name for the same institution overwrites the previous object at that key.

Allowed extensions (case-insensitive)Max size
jpg, jpeg, png, gif, webp, bmp10 MB (10485760 bytes)

Also rejected regardless of extension: a name over 200 characters (the 255-character limit above only guards the field's own length — a name of 201–255 characters passes that check but still fails here with INVALID_INPUT), one containing a path separator (/ or \), .., a control character, or a second, disguised extension (e.g. invoice.php.jpg).

Response

200 OK

{
  "success": true,
  "message": null,
  "errors": null,
  "data": {
    "noticeId": 501,
    "imagePresign": {
      "key": "vWebsite/plugin_cdn/notice/inst_321/sports-day-raw.jpg",
      "post": {
        "url": "https://vidyaone-data-lake.s3.ap-south-1.amazonaws.com/",
        "fields": {
          "key": "vWebsite/plugin_cdn/notice/inst_321/sports-day-raw.jpg",
          "x-amz-server-side-encryption": "AES256",
          "x-amz-credential": "ASIAEXAMPLE/20261012/ap-south-1/s3/aws4_request",
          "x-amz-algorithm": "AWS4-HMAC-SHA256",
          "x-amz-date": "20261012T000000Z",
          "policy": "eyJleHBpcmF0aW9uIjoiMjAyNi0xMC0xMlQwMDowMjowMFoi...",
          "x-amz-signature": "a1b2c3d4e5f6..."
        }
      },
      "expiresIn": 120,
      "maxFileSize": 10485760,
      "contentTypePrefix": "image/"
    }
  }
}

imagePresign is null unless uploadImageFileName was sent.

StatuscodeFires when
400VALIDATION_FAILEDA field constraint above fails, or the body is missing / invalid.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.
400INVALID_INPUTuploadImageFileName has an unsupported or unsafe value (see "Uploading an image" above) — the notice is still created; only the upload slot fails.

Idempotency. Sending the same Idempotency-Key and body again creates a second, separate notice — no duplicate detection is performed.

PUT /notice

Updates a notice belonging to the calling institution. Every writable field is overwritten with the value sent — there is no partial update.

Request

EnvironmentURL
TestingPUT https://api-vweb.vidyaone.com/test/plugin/notice?product={product}
ProductionPUT https://api-vweb.vidyaone.com/plugin/notice?product={product}

Same shape as Create notice, plus notice.noticeId.

Sample request body

{
  "notice": {
    "noticeId": 501,                                                           // required, integer, > 0 — must belong to the caller's institution
    "title": "Annual Sports Day (Updated)",                                    // required, string, max 200 chars
    "description": "Join us for the annual sports day — now with a new venue.", // required, string
    "imageSrc": "sports-day-v2.jpg",                                          // optional, string, max 500 chars — a plain file name only, never a URL or a path; see "Uploading an image" on Create notice — independent of uploadImageFileName
    "publishDate": "2026-11-01",                                              // required, string, date (yyyy-MM-dd)
    "expiryDate": "2026-11-20"                                                // optional, string, date (yyyy-MM-dd) — must be on or after publishDate
  },
  "uploadImageFileName": "sports-day-v2-raw.jpg"                              // optional, string, max 255 chars — see "Uploading an image" on Create notice
}

Uploading an image

Same rules as Create notice's "Uploading an image" — imageSrc and uploadImageFileName are unrelated. Sending uploadImageFileName returns a presigned S3 upload, resolved after the update is already written — an unsupported or unsafe file name fails the request with 400 INVALID_INPUT, but the update has already been applied by that point.

Allowed extensions (case-insensitive)Max size
jpg, jpeg, png, gif, webp, bmp10 MB (10485760 bytes)

Also rejected regardless of extension: a name over 200 characters, one containing a path separator (/ or \), .., a control character, or a second, disguised extension (e.g. invoice.php.jpg).

Response

200 OK

{
  "success": true,
  "message": null,
  "errors": null,
  "data": {
    "updated": true,
    "imagePresign": {
      "key": "vWebsite/plugin_cdn/notice/inst_321/sports-day-v2-raw.jpg",
      "post": { "url": "https://vidyaone-data-lake.s3.ap-south-1.amazonaws.com/", "fields": { "...": "..." } },
      "expiresIn": 120,
      "maxFileSize": 10485760,
      "contentTypePrefix": "image/"
    }
  }
}

imagePresign is null unless uploadImageFileName was sent.

StatuscodeFires when
400VALIDATION_FAILEDA field constraint fails, notice.noticeId missing or not > 0, or the body is missing / invalid.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.
404RECORD_NOT_FOUNDNo matching notice for this institution.
400INVALID_INPUTuploadImageFileName has an unsupported or unsafe value (see "Uploading an image" above) — the update is still applied; only the upload slot fails.

Idempotency. Sending the same Idempotency-Key and body again returns 200 OK and leaves the notice in the same final state.
