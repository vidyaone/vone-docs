vAccount-InstituteAPI — Developer Guide

Documents the Organization, Institute, Onboard, Organization Type, and Institute Type resources.

Postman setup guide

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — you don't need to set any auth header or cookie by hand.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

Common request & response rules

Authentication

Authentication required on every route documented in this guide.

Headers required on every request

HeaderRequiredNotes
Content-Type: application/jsonwrites onlyRequired on any request that carries a body.
Idempotency-Keymutating requestsA UUID the caller generates per request. Required on every POST / PUT / DELETE below. See the Idempotency line under each endpoint for what happens if you resend the same key/body.

Common query parameter

NameTypeRequiredNotes
productstringyesCalling product identifier, e.g. lms. Prefix with test- to run the request in test mode, e.g. test-lms. Required on every route below.

Response envelope

Every response — success or failure — uses the same JSON shape:

{
  "success": true | false,
  "message": "human-readable string" | null,
  "errors":  [ { "code": "...", "message": "...", "field": "..." } ] | null,
  "data":    { ... } | [ ... ] | null
}

Success example (command):

{ "success": true, "message": "Success.", "errors": null, "data": null }

Error example:

{
  "success": false,
  "message": "Validation failed.",
  "errors": [ { "code": "VALIDATION_FAILED", "message": "OrgName is required.", "field": "PostDTO.OrgName" } ],
  "data": null
}

Each entry in errors[] has a machine-readable code — switch on code, not on message text. For validation errors, field is the property path as sent, e.g. PostDTO.OrgName.

JSON bodies accept numeric ids and numbers sent either as numbers or as quoted strings ("instId": 5 and "instId": "5" are equivalent).

Paging (list routes)

pageNumber and pageSize are optional query parameters. A value ≤ 0 is ignored and the default is used; a pageSize above 200 is rejected with 400 VALIDATION_FAILED; a non-integer value is rejected with 400. A pageNumber past the last page returns the last page. On the institute and organization lists, the caller's default item is returned first, then the rest are sorted by name.

StatuscodeFires when

400VALIDATION_FAILEDA request field fails validation, a query value can't be parsed, or the body is missing / not valid JSON.

Organization

Most routes below act only on organizations the caller created or owns. Get organization is the one exception — any authenticated caller can read any organization, with the response shape depending on their relationship to it. A caller may create-or-own at most 10 non-deleted organizations.

POST /org

Creates a new organization for the caller.

Request

EnvironmentURL
TestingPOST https://api-vacc.vidyaone.com/test/inst/org?product={product}
ProductionPOST https://api-vacc.vidyaone.com/inst/org?product={product}

Example request body

{
  "postDTO": {
    "orgName": "Acme Institute",              // required, string, max 150 chars
    "orgTypeId": 1,                           // required, integer, > 0 — must reference an existing organization type
    "regNo": "REG-2024-0007",                 // optional, string, max 50 chars
    "regDate": "2024-04-01T00:00:00Z",        // optional, string, ISO-8601 date-time in UTC (offset +00:00) — omit to leave unset
    "email": "info@acme.example",             // required, string, valid email, max 50 chars
    "website": "https://acme.example",        // optional, string, http or https URL, max 50 chars
    "phoneCode": "+91",                       // optional, string, max 5 chars
    "phone": "9876543210",                    // required, string, exactly 10 digits
    "isWhatsappNumber": true,                 // optional, boolean, default false
    "address": "12 MG Road",                  // required, string, max 500 chars
    "districtId": 49,                        // required, integer, > 0 — must reference an existing record
    "stateId": 26,                            // required, integer, > 0 — must reference an existing record
    "countryId": 1,                          // required, integer, > 0 — must reference an existing record
    "pincode": "560001",                      // required, string, max 10 chars
    "logo": "org/acme/logo.png",              // optional, string, max 100 chars
    "isOwner": true,                          // optional, boolean, default false — false requires ownerName/ownerEmail
    "ownerName": "Asha Rao",                  // conditional, string, max 150 chars — required when isOwner=false
    "ownerEmail": "asha@acme.example",        // conditional, string, valid email, max 150 chars — required when isOwner=false
    "isDefault": true,                        // optional, boolean, default false — caller's first org is always forced default regardless of this value
    "legalDocumentPath": "gst.pdf",           // optional, string, max 255 chars, file name only (no / \ or : characters)
    "legalDocumentType": "GST",               // optional, string, max 50 chars
    "identityProofPath": null,                // optional, string, max 255 chars, file name only (no / \ or : characters)
    "identityProofType": null                 // optional, string, max 50 chars
  }
}

proceedWithKyc and kycStatus are not request fields — nor are remarks/submittedAt, which are set by the server/reviewer only. Sending both legalDocumentPath and identityProofPath results in kycStatus: "Under Review" in later reads; otherwise kycStatus: "Pending".

Response

200 OK

{ "success": true, "message": "Success.", "data": { "orgId": 123 } }
StatuscodeFires when
400VALIDATION_FAILEDA field constraint above fails (including regDate not in UTC or a document value that isn't a file name), or the body is missing / invalid.
400LIMIT_EXCEEDEDThe caller already created-or-owns 10 non-deleted organizations.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.
400INVALID_INPUTorgTypeId / districtId / stateId / countryId doesn't reference an existing record.
409DUPLICATE_RECORDorgName or regNo already in use.

Idempotency. Sending the same Idempotency-Key and body again after a successful create returns 409 Conflict rather than the original success.

PUT /org

Updates an organization the caller created or owns, including its KYC data.

Request

EnvironmentURL
TestingPUT https://api-vacc.vidyaone.com/test/inst/org?product={product}
ProductionPUT https://api-vacc.vidyaone.com/inst/org?product={product}

Same fields as Create organization, nested under putDTO, plus orgId. Every writable field is overwritten with the value sent — there is no partial update. Once the organization has an accepted owner, values sent for isOwner/ownerName/ownerEmail are ignored and the existing owner is kept. Unlike create, isDefault is always honored exactly as sent (no first-organization override).

Sending legalDocumentPath / identityProofPath / legalDocumentType / identityProofType can change kycStatus, following this table (based on the organization's current kycStatus):

Current kycStatusConditionResulting kycStatus
Under ReviewanyRequest rejected with 409 INVALID_STATE — see error table below.
Approved / RejectedBoth documents removedPending
Approved / RejectedA document, or orgName/regNo/address, changedUnder Review
Approved / RejectedNothing above changedUnchanged
Pending / no KYC data yetBoth documents presentUnder Review
Pending / no KYC data yetNot both documents presentPending

    "email": "info@acme.example",             // required, string, valid email, max 50 chars
    "website": "https://acme.example",        // optional, string, http or https URL, max 50 chars
    "phoneCode": "+91",                       // optional, string, max 5 chars
    "phone": "9876543210",                    // required, string, exactly 10 digits
    "isWhatsappNumber": true,                 // optional, boolean, default false
    "address": "12 MG Road",                  // required, string, max 500 chars
    "districtId": 49,                        // required, integer, > 0
    "stateId": 26,                            // required, integer, > 0
    "countryId": 1,                          // required, integer, > 0
    "pincode": "560001",                      // required, string, max 10 chars
    "logo": "org/acme/logo-v2.png",           // optional, string, max 100 chars
    "isOwner": true,                          // optional, boolean — ignored once the org has an accepted owner
    "ownerName": "Asha Rao",                  // conditional, string, max 150 chars — required when isOwner=false; ignored once the org has an accepted owner

404RECORD_NOT_FOUNDThe organization doesn't exist, isn't owned by the caller, is deleted, or is deactivated.

Institute

PUT /, PUT /activate, PUT /deactive, PUT /changeorg, DELETE /, and GET /edit act only on institutes the caller created. PUT /default works on any institute the caller is a member of, and POST /trial requires the caller to be an Admin of the institute. Get institute is the one exception — any authenticated caller can read any institute, with the response shape depending on their relationship to it. List my institutes is broader than the write routes too — it also includes institutes the caller was granted admin access to, without having created them.
