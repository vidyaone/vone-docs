01 Endpoint

A single AWS Lambda behind an API Gateway HTTP API. It validates a cart / buy-now item request, enriches it with device + location info, runs a light bot / dangerous-content check, then fans the event out to SQS (mandatory) and SNS (best-effort). There is no database write here.

MethodPOST for a submission; OPTIONS for CORS preflight. Any other method is treated as POST.
Content-Typeapplication/json. If API Gateway delivers the body base64-encoded (isBase64Encoded), it is decoded automatically before parsing — an invalid base64 / UTF-8 body is 400 "Invalid request body".
Regionap-south-1, account 767750127056.
Handlerlambda_function.lambda_handler
Max body900,000 bytes — checked before JSON parsing.

02 Request headers

HeaderRequirementRule / effect
Idempotency-Key required Must be a GUID (8-4-4-4-12 hex), or the literal opt-out value none (case-insensitive, trimmed). This service does not de-duplicate — the key is validated and passed straight through on the emitted message as idempotencyKey for the downstream consumer to de-dupe on (e.g. so a retried buyNow produces one order, not two). When none is sent, the header requirement is satisfied but the emitted idempotencyKey is an empty string.
Content-Type optional application/json expected. A base64-encoded body is decoded automatically (see §01).
Origin optional Only affects the CORS response headers. Echoed in Access-Control-Allow-Origin when it is https://vidyaone.com or a subdomain (https only). Not a request gate — a non-browser client with no Origin is still processed.
User-Agent optional Parsed into device info. Missing UA, or a known bot substring, is a bot signal (see §06). Also scanned for dangerous content.
Referer optional A missing Referer is a bot signal (see §06).
Authorization optional Permitted by CORS but not currently verified by the Lambda. userId in the body has no session/token check behind it.
CloudFront-Viewer-* optional -Country, -Country-Name, -Country-Region-Name, -City, -Time-Zone — injected by CloudFront when it fronts the API. Populate the location block; each falls back to "".

03 Request payload

JSON object in the HTTP body of a POST request. All field names are camelCase, matching what the vidyaone.com frontend sends directly. 

{

  "serviceId":    0,
  "serviceCode":  "",
  "planId":       2,
  "guestId":      "guest_a1b2c3d4",
  "userId":       0,
  "quantity":     1,
  "price":        4999.00,
  "discount":     500.00,
  "total":        4499.00,
  "buyNow":       true,
  "payAsGuest":   true,
  "billingCycle": "yearly",
  "subscription": true,
  "pageLink":     "https://vidyaone.com/product/1024"
}

04 Identification rule

Simple version: at least one of productId / serviceId must be a positive integer, and a guestId is always required.

  • guestId — always required, on every request.
  • productId or serviceId — at least one must be a positive integer. Sending both as positive is accepted (not rejected); the endpoint does not enforce them as mutually exclusive.
  • Whichever one you're not using can be 0, left out entirely, or omitted — no error either way.
  • userId — always optional, regardless of whether you used productId or serviceId.

One rule on the unused field: if you do send a value for it, it can't be negative. serviceId: -1 is rejected even when productId was valid — 0 or omitting the field entirely are the only accepted ways to say "not applicable."

06 Validation & rejection

Structural checks (run first, in order)

  • Body base64-decoded if isBase64Encoded — bad base64 / UTF-8 → 400 "Invalid request body".
  • Body size ≤ 900,000 bytes (900 KB) — checked before JSON parsing.
  • Body must be valid JSON, and must be a JSON object (not an array, string, etc.).
  • Idempotency-Key header present and valid (see §02).
  • Identification rule (see §04) must be satisfied.

Bot / spam heuristic

Three signals; 2 or more firing together flags the request as a bot:

  • Missing User-Agent header
  • Known bot substring in User-Agent (e.g. bot, curl, python-requests, googlebot…)
  • Missing Referer header

Dangerous content scan

Free-text fields (guestId, serviceCode, pageLink, and the User-Agent header) are scanned, case-insensitively, for substrings like <script, javascript:, onerror=, union select, drop table, ' or '1'='1. A match rejects the request. This is a lightweight heuristic, not a WAF.

Both a bot signal and dangerous content produce the same response: 400 { "error": "Submission rejected" } — the specific reason is only visible in CloudWatch logs, not returned to the caller.

Common rejection messages

  • Header 'Idempotency-Key' is required — header missing or blank
  • Header 'Idempotency-Key' must be a GUID — present but not a GUID and not the none opt-out
  • Payload exceeds 900 KB limit
  • Either 'productId' or 'serviceId' must be a positive integer — neither one is positive
  • Field 'productId' exceeds 2147483647 limit — id above signed 32-bit max (same for serviceId, planId, userId)
  • Field 'total' must be a finite number — NaN / Infinity sent (same for price, discount)
  • Field 'productId' must not be negative / Field 'serviceId' must not be negative — the unused field was sent with a negative value
  • Field 'guestId' is required
  • Field 'guestId' contains disallowed characters
  • Field 'buyNow' is required / Field 'payAsGuest' is required — both must be present and a real boolean
  • Field 'quantity' must be between 1 and 1000
  • Field 'billingCycle' must be one of ['monthly', 'yearly']
  • Submission rejected — bot signals or dangerous content detected

❌ Rejected — missing buyNow / payAsGuest

// 400 — "Submission rejected"

08 Responses

Response headers (all responses)

  • Vary: Origin, X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Strict-Transport-Security, Cache-Control: no-store, no-cache, must-revalidate.
  • For an allowed Origin only: Access-Control-Allow-Origin: <origin>, Access-Control-Allow-Headers: Content-Type,Authorization,Idempotency-Key, Access-Control-Allow-Methods: POST,OPTIONS.
  • Content-Type: application/json on every response except the 302 (which sends Location and no body).
204 No Content

OPTIONS preflight — returned immediately, no body, no validation performed.

200 OK
{
  "message":   "Item received",
  "requestId": "c4d1e2..."
}

Returned when buyNow is false, after the item is durably written to SQS. SNS publish is best-effort and does not affect this response.

302 Found
Location: https://account.vidyaone.com/checkout

Returned instead of 200 when buyNow is true and the request validated cleanly — the item has already been written to SQS by this point. Body is empty; the destination is only in the Location header, configured via config.CHECKOUT_URL. The frontend/client decides how to navigate there (a real browser form POST follows this automatically; a fetch()-based caller will need to read response.url and navigate manually, since a followed redirect does not move the browser tab on its own).

400 Bad Request
{
  "error":     "Field 'guestId' is required",
  "requestId": "c4d1e2..."
}

Returned for any failed validation rule (specific message) or malformed JSON body (generic "Invalid request body" — no internals leaked).

500 Internal Server Error
{
  "error":     "Internal server error",
  "requestId": "c4d1e2..."
}

Returned only if SQS delivery fails (queue outage, permissions, etc.) or an unexpected exception occurs. A failed SNS publish never causes this — it's logged and swallowed.

09 Downstream message (SQS + SNS)

On a clean request the same JSON shape is sent to both the SQS queue (vone-cart-item-queue, mandatory — failure → 500) and the SNS topic (vone-cart-item-topic, best-effort — failure logged, response unaffected). Consumers receive this exact body. 

{
  "requestId":      "c4d1e2...",
  "idempotencyKey": "123e4567-e89b-12d3-a456-426614174000",   // "" when "none" was sent
  "submittedAt":    "2026-09-01T12:00:00+00:00",
  "productId":   1024,
  "planId":      2,
  "serviceId":   0,
  "serviceCode": "",
  "quantity":    1,
  "price":       4999.0,
  "discount":    500.0,
  "total":       4499.0,
  "buyNow":      true,
  "payAsGuest":  true,
  "billingCycle": "yearly",
  "subscription": true,
  "pageLink":    "https://vidyaone.com/product/1024",
  "guestId":     "guest_a1b2c3d4",
  "userId":      0,
  "device":   { "userAgent", "browser", "os", "deviceType", "isMobile" },
  "location": { "countryCode", "countryName", "region", "city", "timezone", "sourceIp" },
  "botDetection": { "isBot": false, "reasons": [] }
}

Note: botDetection.isBot is always false here — a request that trips the bot / dangerous-content heuristic is rejected with 400 before any message is built, so it never reaches SQS/SNS.

10 Request flow

Request → lambda_handler │ ├─ method == OPTIONS? → 204, no processing │ └─ POST → parser.parse(event) │ ├─ base64 decode if isBase64Encoded, else 400 "Invalid request body" ├─ size guard ≤ 900 KB, else 400 ├─ JSON decode must be an object, else 400 ├─ Idempotency-Key header required; GUID or "none", else 400 ├─ identification guestId required; productId or serviceId must be positive (no negatives), else 400 ├─ per-field validation type / range / format checks, else 400 ├─ device + location enrichment (User-Agent, CloudFront headers) ├─ bot heuristic 2+ signals → 400 "Submission rejected" ├─ dangerous content XSS/SQLi patterns → 400 "Submission rejected" │ └─ event built │ ├─ send_sqs() mandatory — failure → 500 └─ publish_sns() best-effort — failure logged, still 200/302 │ ├─ buyNow == true? → 302 redirect, Location: config.CHECKOUT_URL └─ buyNow == false? → 200 "Item received"

Nothing invalid, bot-flagged, or dangerous ever reaches SQS/SNS — every rejection path raises before the message is built or sent.
