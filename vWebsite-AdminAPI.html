1. Overview

Every endpoint is a thin controller that dispatches a MediatR request; business logic lives in the Application layer and all I/O (PostgreSQL, S3, SQS) in the Infrastructure layer. All responses — success or failure — use one JSON envelope (see §3).

ConcernDetail
TransportHTTPS only. GET for reads, POST for writes.
Request bodyContent-Type: application/json (POST only). GET takes query-string only.
AuthSaaS cookie vacc-{product}-auth + a product query parameter on every request. See §2.
CORS / preflightHandled at AWS API Gateway. OPTIONS is short-circuited with a bare 200 before auth.
Tenancyinst_id, user_id, inst_saas_code are read from the validated cookie — never sent in the body. Data is always scoped to the caller's institution.
IdempotencyVIDYAOne clients always send an Idempotency-Key header on mutating calls. This service does not read or enforce it — safety on retry comes from each write being keyed on a natural key (see §2 and each POST).

2. Authentication & the product parameter

Both of the following are required on every call:

RequirementWhereRule
product Query string Required. Your product code (the {product} in the cookie name below), e.g. vweb. Missing / blank → 400 REQUIRED_FIELD. Prefix with test- (e.g. test-vweb) to run in test mode; the prefix is stripped server-side and TestMode=true is set on the request.
vacc-{product}-auth cookie Cookie header Required. HMAC-SHA256 signed token, format {base64url(json-payload)}.{base64url(signature)}. Carries inst_id, user_id, inst_saas_code, product_id, exp, … Missing / invalid signature / expired (30 s skew allowed) / inst_id≤0 / user_id≤0 / blank inst_saas_code → 401 UNAUTHORIZED.
Idempotency-Key header Idempotency-Key header Sent by VIDYAOne clients on every mutating (POST) request by platform convention (a UUID). This service does not read, store, or enforce it — it is accepted and ignored. Retry safety instead relies on the effective key each endpoint de-dupes on (documented per POST below).

Browsers send the cookie automatically for same-site requests. For server-to-server calls, forward the cookie header explicitly.

2.1 Idempotency & safe retries

Because Idempotency-Key is not honoured here, a retried POST is de-duplicated by a natural key, not the header. Each mutating endpoint below states its effective key and what a repeated identical call does. Summary:

EndpointEffective idempotency keyRepeat identical call
POST /data(inst_saas_code, file) — the S3 object keyOverwrites the same object with the same bytes; returns 200 with the same file_key. Not distinguished as create vs update. (Each call mints fresh presigned upload URLs when upload_files is sent.)
POST /module(inst_id, module_name) per array itemLeaves exactly one row per name in the same final module_status; returns 200 data: true. Response does not distinguish created vs updated rows.
POST /page(inst_id, page_name) per array itemLeaves exactly one row per name in the same final page_status; returns 200 data: true. Response does not distinguish created vs updated rows.

GET endpoints are safe/read-only and naturally idempotent. Duplicate-row protection for POST /module and POST /page under concurrent first-time inserts also depends on a DB unique index on (inst_id, <name>) WHERE is_deleted = false.

5. DataJson endpoints

Route prefix data. Reads and writes one tenant-scoped JSON configuration file in S3 (bucket vidyaone-data-lake, key vWebsite/template_database/{inst_saas_code}/{file}). A successful POST also flags the institution's panel as changed so the site gets re-published.

GET /data

Summary. Fetch the parsed contents of one JSON config file for the caller's institution. Call it to load a saved data_* / config_* document before editing.

Request

EnvURL
TestingGET https://api-vweb.vidyaone.com/test/admin/data?product=vweb&file=data_home.json
ParamInTypeRequiredRules

filequerystringyesMust match ^(data_|config_)[A-Za-z0-9_\-]+\.json$; ≤ 255 chars; no .. / path-separators / shell metacharacters.

Headers: Cookie: vacc-{product}-auth=…. No request body.

Response — 200 OK

data is the file's JSON content verbatim (object or array).

{
  "success": true,
  "message": null,
  "data": { "hero": { "title": "Welcome" }, "sections": [ ... ] },
  "errors": null
}

Error responses

HTTPcodeCause
400VALIDATION_FAILEDfile empty, or institution not resolved from cookie.
400INVALID_INPUTFile name fails the pattern, path-traversal detected, stored file is empty, stored file > 10 MB, or stored content is not valid JSON.

Retry guidance: 500 is safe to retry (idempotent read) with backoff. 4xx will not change on retry.

Body fields

FieldTypeRequiredConstraints
filestringyesEnds with .json; matches ^[A-Za-z0-9_][A-Za-z0-9_\-]*\.json$; ≤ 255 chars; no .. / separators / shell metacharacters.
dataobject \| arrayyesMust be a JSON object or array. Max nesting depth 20; max 1000 keys per object; max 10 000 elements per array; serialized payload ≤ 5 MB.
upload_filesarray of objectnoEach item { "file_name": "<name.ext>" }. file_name: ≤ 255 chars; extension in jpg,jpeg,png,gif,webp,bmp,pdf,txt,csv,xlsx,xls,docx,doc; not hidden (no leading .); no dangerous characters.

inst_id, inst_saas_code, test_mode are taken from the cookie and ignored if present in the body.

Example request

POST https://api-vweb.vidyaone.com/test/admin/data?product=vweb
Content-Type: application/json
Cookie: vacc-vweb-auth=eyJ...9c.7f...ab

{
  "file": "data_home.json",
  "data": {
    "hero": { "title": "Welcome", "image": "hero.png" },
    "sections": [ { "type": "text", "body": "About us" } ]
  },
  "upload_files": [
    { "file_name": "hero.png" }
  ]
}

Response — 200 OK

{
  "success": true,
  "message": null,
  "errors": null,
  "data": {
    "message": "File uploaded successfully",
    "file_key": "vWebsite/template_database/<inst_saas_code>/data_home.json",
    "size": 412,
    "upload_presign": {                       // present only when upload_files was sent
      "uploads": [
        {
          "fileName": "hero.png",
          "key": "vWebsite/template_cdn/cdn_<inst_saas_code>/images/hero.png",
          "post": { "url": "https://vidyaone-data-lake.s3.ap-south-1.amazonaws.com/", "fields": { "key": "...", "policy": "...", "x-amz-signature": "..." } },
          "expiresIn": 120,
          "maxFileSize": 10485760,
          "contentTypePrefix": "image/"
        }
      ],
      "rejected": [
        { "file_name": "notes.exe", "reason": "unsupported_file_type" }
      ]
    }
  }
}

Per-file presign problems go into rejected[] (reasons: missing_file_name, unsupported_file_type, presign_generation_failed, or a validation message) — they do not fail the request. Presigned POST URLs expire after 120 s and cap the upload at 10 MB; images land under images/, other types under files/.

Error responses

HTTPcodeCause
400VALIDATION_FAILEDfile empty, data not an object/array, or institution not resolved.
400INVALID_INPUTBad file name, JSON exceeds depth/key/array limits, payload > 5 MB, data not serializable, or a malformed request body.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDCookie missing / invalid / expired.
500INTERNAL_ERRORS3 PutObject failed.

Idempotency. Idempotency-Key is ignored. The effective key is (inst_saas_code, file) — the S3 object path. A repeated identical call overwrites the same object with identical bytes and returns 200 with the same file_key; there is no create-vs-update distinction. Caveat: when upload_files is present, each call generates new presigned upload URLs (the previous ones simply expire after 120 s).

Side effect. After the file is written, the service sets tbl_panel_status.is_data_change = true for the institution (upsert — a panel row is created if none exists). If that write fails, the request still returns 200 (the file is saved); the failure is logged at Error for reconciliation. A 500 from this endpoint means the S3 write itself failed — safe to retry, but retrying re-writes the file.

Request

EnvURL
TestingPOST https://api-vweb.vidyaone.com/test/admin/module?product=vweb

Headers

HeaderRequiredNotes
Content-Type: application/jsonyes—
Cookie: vacc-{product}-auth=…yesSee §2.
Idempotency-Key: <uuid>sent by clientPlatform convention; ignored by this service. Dedupe key is (inst_id, module_name) per item — see §2.1.

Body — JSON array

FieldTypeRequiredConstraints
(root)arrayyesAt least one item.
moduleNamestringyesNon-empty (whitespace-only rejected). Trimmed server-side.
statusbooleannoDefaults to true when omitted.

Example request

POST https://api-vweb.vidyaone.com/test/admin/module?product=vweb
Content-Type: application/json
Cookie: vacc-vweb-auth=eyJ...9c.7f...ab

[
  { "moduleName": "data_home",  "status": true },
  { "moduleName": "data_about", "status": false },
  { "moduleName": "data_blog" }
]

Behaviour

  • Per item: an existing non-deleted row for (inst_id, module_name) has its module_status updated; otherwise a new row is inserted with creator_user_id = the caller's user id.
  • The whole batch is one database transaction.
  • Duplicate names within the same payload → the last occurrence wins.
  • A concurrent insert of the same name is reconciled with one automatic retry (relies on a unique index on (inst_id, module_name) WHERE is_deleted = false).

Idempotency. Idempotency-Key is ignored. The effective key is (inst_id, module_name) per array item. Re-sending the same payload leaves exactly one row per name in the same final module_status and returns 200 data: true. The response does not distinguish rows that were created from rows that were updated.

Response — 200 OK

{ "success": true, "message": null, "data": true, "errors": null }

Error responses

HTTPcodeCause
400VALIDATION_FAILEDEmpty array, an item with empty moduleName, or institution / user not resolved.
400INVALID_INPUTBody is not a JSON array / is malformed.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDCookie missing / invalid / expired.
409DUPLICATE_RECORDUnique conflict that survived the reconcile retry (only if the unique index exists).
500INTERNAL_ERRORDatabase error.

Planned side effect (not yet implemented). After a successful save the handler carries a TODO to email the customer notifying them of the module changes.
