vWebsite-AdminAPI — Developer Guide

Documents the DataJson, Module, Page, and Onboard resources.

Postman setup guide

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — you don't need to set any auth header or cookie by hand.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

Response envelope

Every response — success or failure — uses the same JSON shape:

{
  "success": true | false,
  "message": "human-readable string" | null,
  "errors":  [ { "code": "...", "message": "...", "field": "..." } ] | null,
  "data":    { ... } | [ ... ] | true | null
}

Success example:

{ "success": true, "message": null, "errors": null, "data": true }

Error example:

{
  "success": false,
  "message": "Validation failed.",
  "errors": [ { "code": "VALIDATION_FAILED", "message": "Inst ID must be greater than 0.", "field": "InstSaaSId" } ],
  "data": null
}

Each entry in errors[] has a machine-readable code — switch on code, not on message text.

DataJson

Reads and writes one tenant-scoped JSON configuration file. A successful POST also flags the institution's site as having unpublished changes.

GET /data

Fetch the parsed contents of one JSON config file for the caller's institution. Call it to load a saved document before editing.

Request

EnvironmentURL
TestingGET https://api-vweb.vidyaone.com/test/admin/data?product={product}&file={file}
ProductionGET https://api-vweb.vidyaone.com/admin/data?product={product}&file={file}

Sample request

GET /data?product=vweb
    &file=data_home.json   // required, string, matches ^(data_|config_|plugin_)[A-Za-z0-9_-]+\.json$, max 255 chars

Response — 200 OK

data is the file's JSON content verbatim (object or array).

{
  "success": true,
  "message": null,
  "errors": null,
  "data": { "hero": { "title": "Welcome" }, "sections": [ ] }
}

Error responses

StatuscodeCause
400VALIDATION_FAILEDfile empty, or institution not resolved.
400INVALID_INPUTfile fails the naming pattern, a path-traversal attempt is detected, the stored file is empty or exceeds 10 MB, or the stored content is not valid JSON.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.
404RECORD_NOT_FOUNDNo such file exists for this institution.
502EXTERNAL_SERVICE_ERRORThe file storage backend denied access or failed to return the file's metadata or contents.
POST /data

Create or overwrite one JSON config file for the caller's institution, and (optionally) get presigned upload URLs for binary assets referenced by that file. Call it whenever the customer saves site data.

Request

EnvironmentURL
TestingPOST https://api-vweb.vidyaone.com/test/admin/data?product={product}
ProductionPOST https://api-vweb.vidyaone.com/admin/data?product={product}

Sample request body

{
  "file": "data_home.json",                 // required, string, matches ^(data_|config_|plugin_)[A-Za-z0-9_-]+\.json$, max 255 chars
  "data": {                                  // required, JSON object or array — max nesting depth 20, max 1000 keys per object, max 10000 items per array, serialized size ≤ 5 MB
    "hero": { "title": "Welcome", "image": "hero.png" },
    "sections": [ { "type": "text", "body": "About us" } ]
  },
  "upload_files": [                          // optional, array of objects
    { "file_name": "hero.png" }               // required per item, string, max 255 chars, extension in jpg/jpeg/png/gif/webp/bmp/pdf/txt/csv/xlsx/xls/docx/doc, not hidden, no dangerous characters
  ]
}

Response — 200 OK

{
  "success": true,
  "message": null,
  "errors": null,
  "data": {
    "message": "File uploaded successfully",
    "file_key": "<internal storage path>",
    "size": 412,
    "upload_presign": {                       // present only when upload_files was sent
      "uploads": [
        {
          "fileName": "hero.png",
          "key": "<internal storage path>",
          "post": { "url": "...", "fields": { "key": "...", "policy": "...", "x-amz-signature": "..." } },
          "expiresIn": 120,
          "maxFileSize": 10485760,
          "contentTypePrefix": "image/"
        }
      ],
      "rejected": [
        { "file_name": "notes.exe", "reason": "unsupported_file_type" }
      ]
    }
  }
}

Per-file presign problems go into rejected[] (reasons: missing_file_name, unsupported_file_type, presign_generation_failed, or a validation message) — they do not fail the request. Presigned upload URLs expire after 120 s and cap the upload at 10 MB.

Error responses

StatuscodeCause
400VALIDATION_FAILEDfile empty, data is not an object/array, or institution not resolved.
400INVALID_INPUTfile fails the naming pattern, data exceeds the depth/key/array limits, the serialized payload exceeds 5 MB, data is not serializable, or the request body is malformed.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.
502EXTERNAL_SERVICE_ERRORThe file storage backend rejected the write.

Idempotency. Sending the same Idempotency-Key and body again overwrites the same file with identical bytes and returns 200 OK with the same file_key — same final state, not a new record. When upload_files is sent, each call mints fresh presigned upload URLs regardless.

Side effect. After a successful save, the institution's site is flagged as having unpublished changes. If that flag update fails, this request still returns 200 OK (the file is already saved).

POST /module

Bulk create-or-update module statuses for the caller's institution in one call. Call it when the customer saves the module-settings screen.

Request

EnvironmentURL
TestingPOST https://api-vweb.vidyaone.com/test/admin/module?product={product}
ProductionPOST https://api-vweb.vidyaone.com/admin/module?product={product}

Sample request body

[
  { "moduleName": "data_home",  "status": true  },  // required, string, non-empty (whitespace-only rejected), trimmed server-side
  { "moduleName": "data_about", "status": false },  // status: optional, boolean, default true
  { "moduleName": "data_blog" }
]

data_home and data_school_info are mandatory modules — their status is always forced to true regardless of what's sent.

Behaviour

  • Per item: an existing row for moduleName has its status updated; otherwise a new row is created.
  • The whole batch is saved in one transaction.
  • Duplicate names within the same payload — the last occurrence wins.
  • A plan must exist for the institution — if none does, the whole request fails before anything is saved.
  • After the batch is applied, the total number of modules left with status: true for the institution can never exceed the plan's module limit (see GET /module/limit) — if it would, the whole request fails before anything is saved.

Response — 200 OK

{ "success": true, "message": null, "errors": null, "data": true }

Error responses

StatuscodeCause
400VALIDATION_FAILEDEmpty array, an item with empty moduleName, or institution/caller not resolved.
400INVALID_INPUTBody is not a JSON array, is malformed, or a submitted value fails a database check constraint.
400REQUIRED_FIELDproduct missing, or a required database column was left null.
400LIMIT_EXCEEDEDSaving this batch would leave more modules active (status: true) than the institution's plan allows.
401UNAUTHORIZEDAuthentication required.
404RECORD_NOT_FOUNDNo plan row exists for this institution.
409DUPLICATE_RECORDUnique conflict on module name for this institution.
409FOREIGN_KEY_VIOLATIONThe institution referenced by this request does not exist.

Idempotency. Sending the same Idempotency-Key and body again leaves exactly one row per name in the same final status and returns 200 OK data: true — same final state. The response does not distinguish rows that were created from rows that were updated.

Side effect. After a successful save, the institution's module-setup onboarding step (see GET /onboard/module) is marked complete, and the site is flagged as having unpublished changes. If either flag update fails, this request still returns 200 OK (the modules are already saved).

Events

Fires MODULE_STATUS_UPDATED after the modules are saved.

POST /page

Bulk create-or-update page statuses for the caller's institution in one call.

Request

EnvironmentURL
TestingPOST https://api-vweb.vidyaone.com/test/admin/page?product={product}
ProductionPOST https://api-vweb.vidyaone.com/admin/page?product={product}

Sample request body

[
  { "pageName": "about",   "moduleName": "data_about", "status": true  },  // pageName: required, string, non-empty (whitespace-only rejected), trimmed server-side
  { "pageName": "contact", "moduleName": "data_about", "status": false },  // moduleName: optional, string, trimmed server-side — if set and status is true, this module must currently be enabled; status: optional, boolean, default true
  { "pageName": "blog" }                                                    // moduleName omitted — no module-enabled check applied for this item
]

data_home and data_school_info are mandatory pages — their status is always forced to true regardless of what's sent.

Behaviour

  • Per item: an existing row for pageName has its status (and moduleName) updated; otherwise a new row is created.
  • The whole batch is saved in one transaction.
  • Duplicate names within the same payload — the last occurrence wins.
  • An item cannot be saved with status: true if its named module (moduleName) is currently disabled — the whole request fails before anything is saved. No such check applies when moduleName is omitted.

Response — 200 OK

{ "success": true, "message": null, "errors": null, "data": true }

Error responses

StatuscodeCause
400VALIDATION_FAILEDEmpty array, an item with empty pageName, or institution/caller not resolved.
400INVALID_INPUTBody is not a JSON array, is malformed, or a submitted value fails a database check constraint.
400REQUIRED_FIELDproduct missing, or a required database column was left null.
401UNAUTHORIZEDAuthentication required.
409DUPLICATE_RECORDUnique conflict on page name for this institution.
409FOREIGN_KEY_VIOLATIONThe institution referenced by this request does not exist.
409INVALID_STATEAn item requests status: true for a page whose named module is currently disabled.

Idempotency. Sending the same Idempotency-Key and body again leaves exactly one row per name in the same final status and returns 200 OK data: true — same final state. Created vs updated rows are not distinguished in the response.

Side effect. After a successful save, the institution's site is flagged as having unpublished changes. If that flag update fails, this request still returns 200 OK (the pages are already saved).

Events

Fires PAGE_STATUS_UPDATED after the pages are saved.
