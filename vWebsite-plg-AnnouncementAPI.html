vWebsite-plg-AnnouncementAPI — Developer Guide

Documents the Announcement resource.

Postman setup guide

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — you don't need to set any auth header or cookie by hand.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

Common request & response rules

Authentication required on every route documented in this guide.

Common query parameter

NameTypeRequiredNotes

Response envelope

Every response — success or failure — uses the same JSON shape:

{
  "success": true | false,
  "message": "human-readable string" | null,
  "errors":  [ { "code": "...", "message": "...", "field": "..." } ] | null,
  "data":    { ... } | [ ... ] | true | false | null
}

Success example:

{ "success": true, "message": null, "errors": null, "data": { "announcementId": 801, "imagePresign": null } }

Error example:

{
  "success": false,
  "message": "Validation failed.",
  "errors": [ { "code": "VALIDATION_FAILED", "message": "title is required and must be at most 200 characters.", "field": "Announcement.Title" } ],
  "data": null
}

Each entry in errors[] has a machine-readable code — switch on code, not on message text.

JSON bodies accept numeric ids and numbers sent either as numbers or as quoted strings ("announcementId": 801 and "announcementId": "801" are equivalent).

Announcement

All routes below act only on announcements belonging to the caller's own institution.

GET /announcement

Returns a page of active, non-deleted announcements for the calling institution, most recently published first. createdDate, publishDate, publishState and hasImage are optional filters. Reads from the vw_plg_announcement_list read model.

Request

EnvironmentURL
TestingGET https://api-vweb.vidyaone.com/test/plugin/announcement?product={product}&pageNumber={pageNumber}&pageSize={pageSize}&createdDate={createdDate}&publishDate={publishDate}&publishState={publishState}&hasImage={hasImage}
ProductionGET https://api-vweb.vidyaone.com/plugin/announcement?product={product}&pageNumber={pageNumber}&pageSize={pageSize}&createdDate={createdDate}&publishDate={publishDate}&publishState={publishState}&hasImage={hasImage}
Query paramTypeRequiredConstraints
pageNumberintegerno, default 1A value ≤ 0 (or omitted) is treated as not provided — the default is used, not rejected. Requesting a page past the last page returns the last page instead.
pageSizeintegerno, default 50A value ≤ 0 (or omitted) is treated as not provided — the default is used, not rejected. A value > 200 fails with 400 VALIDATION_FAILED.
createdDatestring, date-timenoISO-8601, must be UTC (offset +00:00). Matches announcements created on the same UTC calendar day as this value (not an exact timestamp match).
publishDatestring, date-timenoISO-8601, must be UTC (offset +00:00). Matches announcements whose publishDate falls on the same UTC calendar day as this value (not an exact timestamp match).
publishStatestringnoMust be one of Scheduled, Live, Expired (exact match).
hasImagebooleannotrue returns only announcements with a non-empty imageSrc; false returns only those without.

Sample request

GET /announcement?product=scl-website
    &pageNumber=1                          // optional, integer, default 1 — ≤0 is ignored (default used), not rejected
    &pageSize=50                           // optional, integer, default 50, max 200 — ≤0 is ignored (default used); >200 fails validation
    &createdDate=2026-10-10T00:00:00Z      // optional, string, ISO-8601 date-time, UTC — matches same UTC calendar day
    &publishDate=2026-11-01T00:00:00Z      // optional, string, ISO-8601 date-time, UTC — matches same UTC calendar day
    &publishState=Live                     // optional, string — one of Scheduled, Live, Expired
    &hasImage=true                         // optional, boolean

POST /announcement

Creates a new announcement for the calling institution.

Request

EnvironmentURL
TestingPOST https://api-vweb.vidyaone.com/test/plugin/announcement?product={product}
ProductionPOST https://api-vweb.vidyaone.com/plugin/announcement?product={product}

Sample request body

{
  "announcement": {
    "title": "Admissions Open for 2026-27",                                   // required, string, max 200 chars
    "description": "We are now accepting admission applications for the 2026-27 academic year. Apply before the last date to secure your seat.", // required, string
    "imageSrc": "admissions-2026.jpg", // optional, string, max 500 chars — a bare, safe file name only (no URL, no path); see "Uploading an image" below — independent of uploadImageFileName, never required to match it
    "publishDate": "2026-11-01T00:00:00Z",                                    // required, string, ISO-8601 date-time, must be UTC (offset +00:00)
    "expiryDate": "2026-12-15T00:00:00Z"                                      // optional, string, ISO-8601 date-time, must be UTC (offset +00:00) — must be on or after publishDate
  },
  "uploadImageFileName": "admissions-2026-raw.jpg"                            // optional, string, max 255 chars — requests an image upload slot; see "Uploading an image" below
}

Uploading an image

imageSrc and uploadImageFileName are unrelated fields — imageSrc is stored exactly as sent, and this API never requires it to match anything the upload flow produces.

Sending uploadImageFileName returns a presigned S3 upload in the response, resolved after the announcement is already created — an unsupported or unsafe file name fails the request with 400 INVALID_INPUT, but the announcement has already been created by that point (data.announcementId in the error is not returned, but the record exists — look it up via List announcements or Get announcement (view) if this happens). On success, POST the raw file bytes plus every field in data.imagePresign.post.fields directly to data.imagePresign.post.url (as multipart form fields, file field last) within expiresIn seconds. Re-uploading the same file name for the same institution overwrites the previous object at that key.

Allowed extensions (case-insensitive)Max size
jpg, jpeg, png, gif, webp, bmp10 MB (10485760 bytes)

Also rejected regardless of extension: a name over 200 characters (the 255-character limit above only guards the field's own length — a name of 201–255 characters passes that check but still fails here with INVALID_INPUT), one containing a path separator (/ or \), .., a control character, or a second, disguised extension (e.g. invoice.php.jpg).

Response

200 OK

{
  "success": true,
  "message": null,
  "errors": null,
  "data": {
    "announcementId": 801,
    "imagePresign": {
      "key": "vWebsite/plugin_cdn/announcement/5a5roCjQmv/admissions-2026-raw.jpg",
      "post": {
        "url": "https://vidyaone-data-lake.s3.ap-south-1.amazonaws.com/",
        "fields": {
          "key": "vWebsite/plugin_cdn/announcement/5a5roCjQmv/admissions-2026-raw.jpg",
          "x-amz-server-side-encryption": "AES256",
          "x-amz-credential": "ASIAEXAMPLE/20261014/ap-south-1/s3/aws4_request",
          "x-amz-algorithm": "AWS4-HMAC-SHA256",
          "x-amz-date": "20261014T000000Z",
          "policy": "eyJleHBpcmF0aW9uIjoiMjAyNi0xMC0xNFQwMDowMjowMFoi...",
          "x-amz-signature": "a1b2c3d4e5f6..."
        }
      },
      "expiresIn": 120,
      "maxFileSize": 10485760,
      "contentTypePrefix": "image/"
    }
  }
}

imagePresign is null unless uploadImageFileName was sent.

StatuscodeFires when
400VALIDATION_FAILEDA field constraint above fails, or the body is missing / invalid.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.
400INVALID_INPUTuploadImageFileName has an unsupported or unsafe value (see "Uploading an image" above) — the announcement is still created; only the upload slot fails.

Idempotency. Sending the same Idempotency-Key and body again creates a second, separate announcement — no duplicate detection is performed.

PUT /announcement

Updates an announcement belonging to the calling institution. Every writable field is overwritten with the value sent — there is no partial update.

Request

EnvironmentURL
TestingPUT https://api-vweb.vidyaone.com/test/plugin/announcement?product={product}
ProductionPUT https://api-vweb.vidyaone.com/plugin/announcement?product={product}

Same shape as Create announcement, plus announcement.announcementId.

Sample request body

{
  "announcement": {
    "announcementId": 801,                                                    // required, integer, > 0 — must belong to the caller's institution
    "title": "Admissions Open for 2026-27 (Extended)",                        // required, string, max 200 chars
    "description": "We are now accepting admission applications for the 2026-27 academic year — deadline extended.", // required, string
    "imageSrc": "admissions-2026-v2.jpg", // optional, string, max 500 chars — see "Uploading an image" on Create announcement — independent of uploadImageFileName
    "publishDate": "2026-11-01T00:00:00Z",                                    // required, string, ISO-8601 date-time, must be UTC (offset +00:00)
    "expiryDate": "2026-12-31T00:00:00Z"                                      // optional, string, ISO-8601 date-time, must be UTC (offset +00:00) — must be on or after publishDate
  },
  "uploadImageFileName": "admissions-2026-v2-raw.jpg"                         // optional, string, max 255 chars — see "Uploading an image" on Create announcement
}

Uploading an image

Same rules as Create announcement's "Uploading an image" — imageSrc and uploadImageFileName are unrelated. Sending uploadImageFileName returns a presigned S3 upload, resolved after the update is already written — an unsupported or unsafe file name fails the request with 400 INVALID_INPUT, but the update has already been applied by that point.

Allowed extensions (case-insensitive)Max size
jpg, jpeg, png, gif, webp, bmp10 MB (10485760 bytes)

Also rejected regardless of extension: a name over 200 characters, one containing a path separator (/ or \), .., a control character, or a second, disguised extension (e.g. invoice.php.jpg).

Response

200 OK

{
  "success": true,
  "message": null,
  "errors": null,
  "data": {
    "updated": true,
    "imagePresign": {
      "key": "vWebsite/plugin_cdn/announcement/5a5roCjQmv/admissions-2026-v2-raw.jpg",
      "post": { "url": "https://vidyaone-data-lake.s3.ap-south-1.amazonaws.com/", "fields": { "...": "..." } },
      "expiresIn": 120,
      "maxFileSize": 10485760,
      "contentTypePrefix": "image/"
    }
  }
}

imagePresign is null unless uploadImageFileName was sent.

StatuscodeFires when
400VALIDATION_FAILEDA field constraint fails, announcement.announcementId missing or not > 0, or the body is missing / invalid.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.

400INVALID_INPUTuploadImageFileName has an unsupported or unsafe value (see "Uploading an image" above) — the update is still applied; only the upload slot fails.

Idempotency. Sending the same Idempotency-Key and body again returns 200 OK and leaves the announcement in the same final state.
