vAccount-UserAPI — Developer Guide

Documents the SaaS and User resources.

Postman setup guide

  1. Use Postman for web (web.postman.co), not the desktop app.
  2. Install the Postman Interceptor Chrome extension — it lets Postman's web app read cookies from your Chrome session.
  3. Enable Interceptor, then log into the product normally in Chrome. Once logged in, your session is available to Postman automatically — you don't need to set any auth header or cookie by hand.
  4. Download the collection from the link in the navbar above and import it into Postman, then send requests — it's pre-configured for Testing.

Common request & response rules

Authentication

Authentication required on every route documented in this guide.

Headers required on every request

Content-Type: application/jsonwrites onlyRequired on PUT /user.
Idempotency-Keymutating requestsA UUID the caller generates per request. Required on PUT /user. See the Idempotency line under that endpoint for what happens if you resend the same key/body.

Common query parameter

NameTypeRequiredNotes
productstringyesCalling client-app identifier, e.g. scl-website. Prefix with test- to run the request in test mode, e.g. test-scl-website. Required on every route below.

Response envelope

Every response — success or failure — uses the same JSON shape:

{
  "success": true | false,
  "message": "human-readable string" | null,
  "errors":  [ { "code": "...", "message": "...", "field": "..." } ] | null,
  "data":    { ... } | null
}

Success example (command):

{ "success": true, "message": "User updated successfully.", "data": { "uploadPresign": null }, "errors": null }

Error example:

{
  "success": false,
  "message": "Validation failed.",
  "errors": [ { "code": "VALIDATION_FAILED", "message": "Full name is required.", "field": "PutDTO.FullName" } ],
  "data": null
}

Each entry in errors[] has a machine-readable code — switch on code, not on message text. For validation errors on PUT /user, field is the property path as sent, e.g. PutDTO.FullName or PutDTO.SocialLinks[0].Platform.

JSON bodies accept numeric ids and numbers sent either as numbers or as quoted strings ("countryId": 1 and "countryId": "1" are equivalent).

Status & error codes used in this guide

StatuscodeFires when

302—GET /saas/userinstdetail only — the institute's plan has expired. See that endpoint.

PUT /user

Overwrites the caller's profile and replaces their social links. Every writable field is overwritten with the value sent — there is no partial update, so always send the complete object, including socialLinks. Optionally, in the same call, also issues a presigned S3 upload for a new profile picture — set uploadProfilePictureFileName and the response includes uploadPresign; set putDTO.profileImageUrl yourself to the resulting URL (the object key is deterministic from the file extension, so you don't need to wait for the upload to finish to know it) and actually upload the file to S3 afterward using the returned presign.

Request

EnvironmentURL
TestingPUT https://api-vacc.vidyaone.com/test/user/user?product={product}
ProductionPUT https://api-vacc.vidyaone.com/user/user?product={product}

Sample request

PUT /user?product=test-scl-website
    // required, string — see "Common query parameter" above

Example request body

    "gender": "Female",                                       // optional, string, max 20 chars
    "profileImageUrl": "https://cdn.example.com/u/10432.jpg", // optional, string, max 200 chars
    "address": "12 MG Road, Bengaluru",                       // optional, string, max 1000 chars
    "countryId": 1,                                           // optional, integer, > 0
    "stateId": 26,                                            // optional, integer, > 0
    "districtId": 49,                                         // optional, integer, > 0
    "pinCode": "560001",                                      // optional, string, max 10 chars
    "employeeId": "EMP-1042",                                 // optional, string, max 50 chars
    "designation": "Administrator",                           // optional, string, max 100 chars
    "department": "Operations",                               // optional, string, max 100 chars
    "workEmail": "asha.rao@sunrise.edu",                      // optional, string, max 150 chars, valid email
    "qualification": "M.Sc.",                                  // optional, string, max 150 chars
    "dateOfJoining": "2022-06-01",                             // optional, string, date (YYYY-MM-DD)
    "employmentType": "Full-time",                            // optional, string, max 50 chars
    "socialLinks": [                                          // optional, array, max 50 items — the caller's complete list; a link not included here is removed
      {
        "socialLinkId": 7,                                     // required, integer, 0 = new link, > 0 = update one of the caller's existing links
        "platform": "LinkedIn",                                // required, string, max 50 chars, unique within this array (case-insensitive)
        "profileUrl": "https://linkedin.com/in/asha"           // required, string, max 500 chars, http(s) URL
      },
      {
        "socialLinkId": 0,
        "platform": "YouTube",
        "profileUrl": "https://youtube.com/@asha"
      }
    ]
  },
  "uploadProfilePictureFileName": "profile.jpg"   // optional, string, max 255 chars — only the extension is used; must be jpg, jpeg, png, gif, webp, or bmp. When set, the response also includes a presigned upload for this file.
}

userId and email are not request fields — identity is taken from the authentication cookie, not the body. putDTO.profileImageUrl is saved exactly as sent, even if it points at a file not uploaded yet — set it yourself to vAccount/user_profile/{userId}/profile.{ext}'s resulting URL (same extension as uploadProfilePictureFileName) before or after the actual S3 upload.

Response

200 OK

{
  "success": true,
  "message": "User updated successfully.",
  "data": {
    "uploadPresign": {
      "key": "vAccount/user_profile/10432/profile.jpg",
      "post": {
        "url": "https://vidyaone-data-lake.s3.ap-south-1.amazonaws.com/",
        "fields": {
          "key": "vAccount/user_profile/10432/profile.jpg",
          "x-amz-server-side-encryption": "AES256",
          "x-amz-credential": "AKIA...redacted/20261008/ap-south-1/s3/aws4_request",
          "x-amz-algorithm": "AWS4-HMAC-SHA256",
          "x-amz-date": "20261008T000000Z",
          "policy": "eyJ...redacted",
          "x-amz-signature": "a1b2...redacted"
        }
      },
      "expiresIn": 120,
      "maxFileSize": 2097152,
      "contentTypePrefix": "image/"
    }
  },
  "errors": null
}

uploadPresign is null when uploadProfilePictureFileName was not sent. When present: upload directly to uploadPresign.post.url as multipart/form-data, including every entry in post.fields as a form field (unchanged, in order) plus the file content itself as a final field named file. S3 enforces maxFileSize (bytes) and requires the uploaded Content-Type to start with contentTypePrefix; the whole presigned POST expires after expiresIn seconds. key is always vAccount/user_profile/{userId}/profile.{ext} — fixed per caller and file type, so re-uploading the same image type always overwrites the previous picture (uploading a different image type afterward leaves the old file's object behind under its own extension). The response does not include a public URL for the uploaded file.

StatuscodeFires when
400VALIDATION_FAILEDA field constraint above fails (including uploadProfilePictureFileName over 255 chars), putDTO is missing, or the body is missing / invalid.
400INVALID_INPUTuploadProfilePictureFileName's extension is not one of jpg, jpeg, png, gif, webp, bmp. The profile is not updated when this fires.
400REQUIRED_FIELDproduct missing.
401UNAUTHORIZEDAuthentication required.
404RECORD_NOT_FOUNDNo profile record exists for the caller, or a submitted socialLinkId > 0 doesn't belong to the caller.
409DUPLICATE_RECORDA submitted social link collided with an existing one.
409CONCURRENCY_CONFLICTThe profile was updated by another request at the same time.
409FOREIGN_KEY_VIOLATIONcountryId / stateId / districtId doesn't reference an existing record.

Idempotency. Sending the same Idempotency-Key and body again returns 200 OK and leaves the profile in the same final state; if uploadProfilePictureFileName was set, a new presigned POST is issued each time (signature and x-amz-date differ) for the same key — safe to retry.
